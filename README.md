# 这个项目在做什么

这个项目研究一件事：工具调用很多以后，怎样把暂时用不到的旧记录从模型输入里拿开，等真的需要时再准确找回来。

程序内部仍叫 `TraceGraph`。它的作用是记录“哪次工具调用产生了什么结果、后面的哪一步用了这个结果、失败后来是否解决”等关系。本文把 token 叫作“模型输入量”；token 是模型计算输入长度和费用时使用的单位。SHA-256 是给文件计算指纹的标准办法，用来确认保存的结果没有被改动。

## 最重要的结果

第六阶段一共测试了 72 种情况：

- 把所有旧记录一直放在输入里最稳，但内容最长。
- 只收起旧记录、不允许找回，遇到追问旧事时全部失败。
- 只按关键词找旧记录，经常只能找到一部分，缺少前因后果。
- 按记录之间的关系把前因后果一起找回来，72 种情况全部完成，没有误删当前任务必需的信息。
- 完整输入量的中位数从 2041 降到 942.5，约少 54%。

这些题都是项目自己设计的，没有让真实模型处理真实编程任务。因此目前只能说“这个办法值得继续验证”，不能说“已经证明对真实编程助手普遍有效”。

另有一项比较没有分清作用：当同一个错误再次发生时，请求同时也像一次历史追问，所以无法单独判断“错误再次发生”这条找回规则是否必要。项目不会把这项结果写成已证明。

完整数字见[第六阶段自己设计的测试结果](docs/第六阶段_自己设计的测试结果.md)。代码名与普通话解释见[项目里的常用说法](docs/项目里的常用说法.md)。

### 后续真实模型小规模试跑

2026-08-30 又用阿里云百炼的 `qwen3.8-27b` 跑了 216 次，仍然使用上面这些项目自己设计的题，不是真实编程任务。正式记录是：

- 所有旧记录一直保留的办法得到 32/36；人工复核发现其中 4 条实际答对了，是固定的关键词检查过严，但正式分数不在看到结果后改动。
- 按前因后果找回的办法得到 27/36；在 12 次历史追问中得到 6/12，高于只收起不找回的 2/12，也高于按关键词找回的 3/12。
- 这个办法有 3 次返回了无法解析的 JSON（程序约定的结构化文字格式）。其余 33 次没有表示要重复副作用，但这 3 次无法证明安全，所以按事先规则停止，不扩大到外部公开任务。
- 正式运行加最小检查共请求 217 次，花费约 1.272 元；连同修正前的两次最小检查，总花费约 1.275 元，低于 100 元上限。

完整数字和判分问题见[第六阶段真实模型小规模试跑结果](docs/第六阶段_真实模型小规模试跑结果.md)。

## 程序怎样工作

每次准备调用模型时，程序会：

1. 找出当前目标、仍未完成的步骤、限制条件、已经确认的操作和仍未解决的错误。
2. 保留当前任务一定会用到的记录。
3. 把暂时无关的旧记录单独保存，但不删除原件。
4. 用户追问旧事、恢复旧目标、再次遇到同类错误或明确引用旧记录时，再找回相关内容。
5. 找回时把工具调用与返回结果成对补齐，并区分“过去的事实”和“现在的事实”。
6. 拿不准时宁可多保留，或者明确停止，不编造缺失的前因后果。

## 以前各阶段得到什么

| 阶段 | 大白话结论 |
|---|---|
| 第二、第三阶段 | 建成了记录、保存、比较和检查工具；真实模型比较没有形成足够强的正面证据。 |
| 第四阶段 | 原定减少 30% 完整输入量的目标，在固定规则和工具说明成本下最多只能达到 28.451%，所以停止后续真实实验。 |
| 第五阶段 | 安全检查通过，但 185 个可比较时刻的输入量中位差为 0，没有实际节省，因此停止下一步。 |
| 第五阶段补充 | 尝试让模型判断哪些旧记录还需要；格式问题得到改善，但不同运行之间的判断仍不够稳定，不能作为标准答案。 |
| 第六阶段 | 自己设计的 72 种本地情况全部跑通；随后完成 216 次真实模型小规模试跑，但继续条件没有全部达到，已停止在外部公开任务之前。 |

历史数字和停止理由没有因为本次文字改写而改变。

## 怎样运行

项目使用 Python 3.11。下面的命令名和参数保持不变：

```powershell
$env:PYTHONPATH = "src"
python -m pytest
python -m tracegraph --help
```

运行第六阶段的本地检查：

```powershell
$env:PYTHONPATH = "src"
python scripts/analyze_phase6_controlled.py --input outputs/phase6/e1_controlled_v1
```

只读检查已经完成的真实模型小规模试跑，不会再发请求：

```powershell
$env:PYTHONPATH = "src"
python scripts/analyze_phase6_live_pilot.py
```

只读查看新版自动判分和公开测试任务准备结果：

```powershell
$env:PYTHONPATH = "src"
python scripts/analyze_phase6_live_scoring_fix.py
python scripts/analyze_phase6_benchmark_preparation.py
```

不要再次运行生成命令覆盖现有结果。结果目录采用“已经存在就拒绝写入”的规则。

### 失败历史压缩 Benchmark

仓库新增 `compression_audit_v1`，专门测量压缩后是否丢失“失败方法、失败原因、切换决定和成功替代方案”，以及为重新获得这些事实增加的真实调用、模型输入量、时间和费用。原有 72 个结果保留为不参与排名的兼容诊断；新受控集是 240 个独立前缀和 1,440 个 episode。

```powershell
$env:PYTHONPATH = "src"
python -m tracegraph benchmark-build --config configs/compression_audit_v1.json --output outputs/compression_audit/my_build
python -m tracegraph benchmark-validate --dataset outputs/compression_audit/my_build
python -m tracegraph benchmark-run --config configs/compression_audit_v1.json --dataset outputs/compression_audit/my_build --output outputs/compression_audit/my_run --mode deterministic
python -m tracegraph benchmark-score --dataset outputs/compression_audit/my_build --run outputs/compression_audit/my_run --output outputs/compression_audit/my_score
```

当前正式 `v1.0` 仍受 100 条真实轨迹双人标注门禁约束，不能用未核验候选替代。协议、指标、费用保护和复现方法见[失败历史压缩 Benchmark 说明](docs/失败历史压缩Benchmark说明.md)，真实数据流程见[失败历史真实轨迹标注指南](docs/失败历史真实轨迹标注指南.md)。

2026-08-31 已完成 v0.1 的 272 个 episode、321 次真实请求，按标价约 2.9268 元。全矩阵未通过机制验收；请求快照记录问题已通过独立账本修复，原始结果保留，答案分数与成本未变。最终 282 项测试通过。详见 [v0.1 冻结诊断运行报告](docs/失败历史压缩Benchmark_v0.1运行报告.md)。

导入 τ³-bench（一个公开的工具调用测试集）保存结果：

```powershell
$env:PYTHONPATH = "src"
python -m tracegraph import-tau `
  --input path\to\tau-results `
  --output data\processed\tau-graphs `
  --archive artifacts\tau-archive
```

API 是程序之间发送请求的接口。运行任何会调用外部模型 API 的脚本前，必须重新确认模型、价格、费用上限和停止条件，并取得用户明确授权。

## 不能越过的边界

- “从模型输入里拿开”不等于删除原始记录。
- 自己设计的测试不能冒充真实任务效果。
- 没有运行的实验必须写“没有运行”。
- 本地估算的模型输入量不能冒充模型服务商账单。
- 缺少标准答案、实际用量、文件指纹或来源记录时，相应结论不能写成已证明。
