# 数据和结果文件怎么存

<!-- 大白话说明 -->
这份文档说明数据和结果文件怎么存。下文保留已经采用的接口、规则和历史数字，只把说明改成更容易理解的普通话。本文没有修改程序接口、结果数据或旧文件指纹，也没有新增外部实验。

## 第五阶段第二次补充 artifacts

第五阶段第二次补充 的 create-only 根为 `outputs/phase5_2/e0_glm_pseudolabel_v1`：

- `frozen_config.json` / `pricing_snapshot.json`：固定模型、价格核验、预算、划分、继续或停止条件和 15 个 `ToolEffectSpec`；
- `requests/*.json`：370 个无凭据的冻结 模型服务商 request；
- `mappings/*.json`：pass-specific opaque event/span ID 与原 ID 的隔离映射；
- `request_index.jsonl`：request/截至当时已有的记录/pass/split/文件指纹/估算 token 索引；
- `no_opportunity_prefixes.jsonl`：76 个无历史完整工具 span、模型服务商 requests=0 的 截至当时已有的记录；
- `raw_responses/*.json`：每次 HTTP 尝试的脱敏原始响应，文件名含 attempt；
- `usage_ledger.jsonl`：append-only HTTP status、usage、验证状态和响应文件指纹；
- `labels/*.json`：通过 schema/ID 校验的 opaque 与原 ID 双视图标签；
- `parsed_machine_labels.jsonl` / `machine_consensus.jsonl`：只在 370 请求完成后生成；
- `pseudolabel_summary.json` / `pseudolabel_gate.json`：机器稳定性前门；
- `state_machine/predictions.jsonl`、`prefix_rows.jsonl`、`summary.json`、`gate.json`：只在伪标签前门通过后生成；
- `manifest.json`：完成或继续或停止条件停止时的最终逐文件文件指纹清单；收集暂停时不存在，避免把部分结果伪装成完成 artifact。

机器标签字段为 `disposition`、`terminal_reason`、`relation_target_ids`、`obligations`、
`evidence_event_ids`、`reactivation_risk`。`machine_consensus` 只比较前四项；证据事件取两遍
并集，任一核心字段分歧时 disposition/reason 退化为 `uncertain/unknown`。

`LifecyclePrediction` 额外保存 source/target event、entity key、field scope、verifier、
confidence、obligations 和 来源记录。所有预测与离线整理后交给模型的内容属于 development evidence，
不得写回原 工具使用记录之间的关系 或发送给 模型服务商。

## 第五阶段 判断记录现在是否还需要 artifacts

第五阶段 使用 `phase5_liveness_config_v1`，记录整理办法 为
`lifecycle_graph_context/lifecycle_graph_context_v1`。所有新输出只写入
`outputs/phase5/`；`outputs/gdsc_r0_audit`、`outputs/gdsc_r2_1` 和
`outputs/phase4` 是只读保护根。

### `DecisionLifecycleGraph`

- `schema_version=decision_lifecycle_graph_v1`；
- 截至当时已有的记录-only `DecisionStateGraph`；
- neutral `event_graph_hash`，排除可被旧 判断记录现在是否还需要 engine 更新的派生状态；
- `event_records[]`：event ID、terminal/nonterminal status、确定性 reason、confidence、
  source atom IDs；
- `lifecycle_hash`：canonical JSON digest。

### `LivenessRoots`

- `schema_version=liveness_roots_v1`；
- 判断记录现在是否还需要/query 文件指纹；
- roots：atom/event 来源记录、root reason、hard flag；
- uncertainty reasons；
- root atom/event IDs 与 `roots_hash`。

### `LiveSubgraph`

- `schema_version=live_subgraph_v1`；
- live/evicted atom、node 和 span IDs；
- `EventSpan` 的 message ordinals、parallel call IDs、raw refs；
- root/closure 来源记录；
- 每个 event 的 判断记录现在是否还需要 reason；
- 单独保存的旧记录/protocol 不确定性记录；
- `live_subgraph_hash`。

### `LifecycleContextView`

- `schema_version=lifecycle_context_view_v1`；
- final messages/tools 与保留的原始 message ordinals；
- live/evicted node/span IDs；
- root、closure、判断记录现在是否还需要、fallback 和 uncertainty 记录；
- `projection_strategy=gdsc_prune_v1`；
- 五层 `PromptCost`、soft/hard budget 状态；
- protocol validity、`send_eligible` 与 request 文件指纹；
- 模型服务商 actual usage 只能以同一 request 文件指纹 append/join。

所有 dataclass artifact 均支持 canonical `to_dict()`、文件指纹 校验和 拿不准时宁可保留或停止
round trip。空的 第五阶段 query-找回旧记录 扩展字段不会进入历史
`decision_query_v1` JSON，因此不改变旧 query 文件指纹。

### F5-E0 冻结与回放包

`outputs/phase5/e0_development_v1/` 是 append-only 第五阶段 离线结果根：

- `tool_schemas.json`：本地 τ³ retail/airline native OpenAI tool schemas 和
  `artifact_sha256`；
- `development_prefix_manifest.json`：全部 261 个 outcome-blind 截至当时已有的记录、源文件与
  截至当时已有的记录/policy/schema 文件指纹、结构特征、预冻结 F5-G1 阈值和 `manifest_sha256`；
- `prune_replay_v1/`：保留的首次审计尝试；其 单独保存的旧记录 equality 口径错误，不作权威
  F5-G1 裁决；
- `prune_replay_v2/prefix_rows.{jsonl,csv}`：逐 截至当时已有的记录 FullRaw/Prune 请求 文件指纹、
  判断记录现在是否还需要 artifacts、协议/召回/找回旧记录 和完整 真正拼成完整请求后的 cost；
- `prune_replay_v2/summary.json`、`f5_g1_gate.json`、`run_manifest.json`：聚合指标、
  冻结阈值逐项裁决与逐文件 文件指纹。

所有 builder/evaluator 均拒绝已存在的 output root，不覆盖旧尝试。单独保存的旧记录恢复比较的是
content-addressed raw 模型服务商 payload 与其 SHA-256 存放编号；原始 模型服务商 envelope
不要求等于图中的规范化 node content。

## 第四阶段的记录整理办法 canonical artifacts

第四阶段的记录整理办法 新产物使用 canonical JSON（UTF-8、稳定 key 排序、无随机 UUID）计算 ID、state 文件指纹 和 request 文件指纹。旧 工具使用记录关系图 JSON 不迁移、不改 文件指纹。

### `DecisionStateGraph`

- `schema_version`、`session_id`、`cutoff`、`event_graph_hash`；
- `atoms[]`：`atom_id`、kind、value、verification status、confidence、判断记录现在是否还需要、来源记录 event IDs；
- `edges[]`：稳定 edge ID、source、target、relation、来源记录；
- `state_hash`：排除运行时间等非语义字段后的 canonical digest；
- `reducer_version` 与 parser 来源记录。LLM parser 产物只能标为低置信 provisional，不能直接成为 hard fact。

### `DecisionQuery`

- pending operation、retry context、candidate tools、required slots、policy scope；
- query 文件指纹 与所依赖 state/event IDs；
- 不确定时保留候选工具和扩大交给模型的内容的理由，不记录“猜定的单工具”。

### `PromptBundle`

- 最终 `messages` 与 `tools`；
- `representation_manifest[]`：source IDs、representation kind、payload 文件指纹、verification 与 omission-risk；
- `closure_provenance`、`compiler_decision_log`、`request_hash`；
- `costs`：`graph_selected`、`compiled`、`protocol_closed`、`serialized_request`、`provider_actual`；
- `budget`：soft budget、模型服务商 hard limit、`conservative_over_budget`、`matched_budget_eligible`；
- task、policy、tool schema、模型服务商 protocol、serializer、tokenizer、记录整理办法/risk artifact 来源记录。

`serialized_request` 对完整 system、messages、tool schemas 和协议格式开销计量。`provider_actual` 只在真实返回 usage 后回填，禁止用本地估算冒充。

### R0–R4 结果包

- `prompt_cost_profile.json`：逐 turn 五层成本及 192-view 错位复现；
- `benchmark_eligibility.json`：按域的 task/action/dynamic-history/headroom/判断记录现在是否还需要/snapshot/evaluator 检查；
- `risk_model.json`：冻结特征、task-held-out split、校准参数、指标和训练输入 文件指纹；
- `prefixes/<prefix_id>/`：conversation、environment snapshot、工具使用记录之间的关系、DecisionStateGraph、DecisionQuery、tool schema、representation payload 与全部 文件指纹；
- `gdsc_gate_report.json`：逐 继续或停止条件 布尔值、观测值、阈值、输入 artifact 文件指纹 与停止原因；
- `request_artifacts/`：发送前冻结的 request；模型服务商 usage 以 append-only completion record 关联 request 文件指纹。

R2.1 诊断包位于 `outputs/gdsc_r2_1/`：

- `baseline_manifest.json`：历史输入文件 文件指纹 与 embedded-文件指纹 验证；
- `cost_attribution.json`：总体/分域中位数、发送对象一致率与可达性裁决；
- `cost_attribution_rows.csv`：261 个 decision points 的完整成本、leave-one-component-out marginal、fixed floor 与 constructive floor；
- `attainability_report.json`：互斥分支、blockers 与下一动作；
- `cost_attribution_component_medians.csv`、`fixed_cost_reachability.svg`：非可加组件中位数和固定成本可达性图。

`provider_requests.jsonl` 从 serializer v2 起同时记录 `prompt_request`/`prompt_request_sha256` 与 `invocation_request`/`invocation_request_sha256`。模型服务商 input token 与 PromptBundle request 文件指纹 只使用前者的 model/messages/tools；生成控制参数不混入 prompt token 口径。

完整 schema 与阶段状态见 [第四阶段的记录整理办法 实验开始前定下的规则](第四阶段_实验开始前定下的规则.md)和 [第四阶段的记录整理办法 结果账本](第四阶段新方案做了什么和得到什么.md)。

## 历史 工具使用记录关系图 格式

### 工具使用记录关系图 JSON

顶层字段：

- `schema_version`
- `session_id`
- `metadata`：benchmark、task、trial、reward、来源记录 等
- `nodes[]`：类型、内容、step、记录现在是否还需要、token、raw_ref、side_effect
- `edges[]`：source、target、类型、confidence、metadata

`tracegraph validate-trace <path>` 同时检查端点、边签名、side-effect 原始引用和 archived 节点可恢复性。

### 单独保存的旧记录

单独保存的旧记录路径为 `objects/<sha-prefix>/<sha>.json`，存放编号 格式为 `sha256:<digest>`。对象 envelope 包含 payload、metadata、写入时间和 digest。`verify-archive` 会重新计算所有 文件指纹。

### 历史实验输出

- `manifest.json`：来源记录、预算、记录整理办法、项目自己设计的测试 标记、文件清单。
- `per_session.jsonl/csv`：每个 session × 记录整理办法的指标。
- `aggregate.json`：按 记录整理办法 聚合。
- `context_views.jsonl`：选中内容、理由和 source node。
- `lifecycle_analysis.json`：状态与转移频数。
- `oracle_upper_bound.json`：post-hoc 结构 Oracle。
- `online_replay.jsonl`：按 step 截至当时已有的记录回放，保证不读取未来节点。

Live 同题比较 组合实验 聚合额外输出：

- `live_matrix_report.json`：完整性、每个 记录整理办法的官方 success/stop/infra、selected-context tokens、task+trial 配对、exact McNemar 与 按同一批题反复抽样得到的估计范围。
- `live_matrix_sessions.csv`：每个真实 session 的 reward、termination、记录整理办法、budget、工具使用记录和 context-view 统计。

第四阶段 额外输出：

- `failure_chain_v2/annotation_key.json`：状态/原因拆分后的隐藏 prediction key；
- `failure_chain_v2/human_annotator_{a,b}.csv`：不含 Codex 标签泄漏的人工盲表；
- `failure_chain_v2/migration_audit.json`：v1 输入 文件指纹、逐包行数和 lossy 映射计数；
- `post_failure_phase3_diagnostic/events.jsonl`：failure × next-3-action 的动作级记录；
- `post_failure_phase3_diagnostic/sessions.csv`：session 级窗口聚合；
- `post_failure_phase3_diagnostic/report.json`：完整性、条件聚合、输入文件 文件指纹 与解释警告；
- trajectory store 的 `generation.json` / `generation_complete.json`：evaluator 前冻结的完整生成；
- `evaluation_attempts/attempt_NNNN/`：append-only 文件清单、raw responses 和成功/错误 result；
- `merged.json`：由 simulation id、generation 文件指纹 和 evaluation 文件指纹 约束的 reward 合并结果。

原始 benchmark 数据、单独保存的旧记录 和正式 outputs 默认不入 Git，避免泄露数据或把昂贵实验产物混入源码。

## 第五阶段第一次补充 evidence-ceiling artifacts

`outputs/phase5_1/e0_evidence_ceiling_v1/` 是 create-only 目录：

- `prefix_rows.jsonl` / `prefix_rows.csv`：每个冻结 截至当时已有的记录 的 Grade A/B 关系、verifier、
  evidence/report 文件指纹、三种真正拼成完整请求成本和协议/安全检查；值本身只保存类型绑定的 SHA-256；
- `summary.json`：261/185 总体计数、Raw/F5/Grade-A/ceiling 成本和无 outcome/模型服务商 访问声明；
- `p51_g0_gate.json`：预冻结 93-截至当时已有的记录 与 同题比较-median 继续或停止条件及 blockers；
- `run_manifest.json`：上述文件的逐文件大小和 SHA-256。

`LifecycleEvidenceRecord.may_generate_hard_dead=true` 只允许 Grade A 且
`confidence=1.0`。Grade B 记录必须为 false。`LifecycleEvidenceReport.report_hash` 覆盖 cutoff、
截至当时已有的记录 graph 文件指纹、配置 文件指纹 和排序后的全部证据记录。
