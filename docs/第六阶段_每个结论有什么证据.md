# 第六阶段：每个结论有什么证据

这份文档防止把计划、程序检查和自己设计的题夸大成真实效果。当前支持六项本地结论；真实模型小规模试跑已经完成但没有达到全部继续条件，跨模型和跨任务结论没有运行。错误再次发生时那条专门找回规则的独立作用没有分清，因此不支持相关必要性结论。

状态只能使用 `supported`、`unsupported` 或 `not run`。

| 编号 | 想说的结论 | 实际证据 | 状态 |
|---|---|---|---|
| `P6-C0` | 第六阶段没有改动第一至第五阶段旧结果 | 旧结果目录前后文件指纹相同，只读检查通过 | `supported` |
| `P6-C1` | 程序只看已有记录，结果稳定，拿不准时会保留 | 不偷看后续、保存原文损坏、未知关系和工具调用配对测试通过 | `supported` |
| `P6-C2` | 自己设计的题足以进行本地比较 | 24 段已有记录、72 种后续和全部进入条件通过 | `supported` |
| `P6-C3` | 可以安全收起旧记录并减少当前输入 | 必须保留内容完整度 1.0，误删为 0，输入量估计范围全部小于 0 | `supported` |
| `P6-C4` | 需要时找回旧记录能修复只收起不找回的问题 | `M5` 对 `M3` 的追问旧事完成率高 1.0 | `supported` |
| `P6-C5` | 补齐前因后果比只按关键词找更完整 | 相同 1024 上限下，`M5` 的完整度和有用内容比例估计范围都高于 `M4` | `supported` |
| `P6-C6` | 在自己设计的题中，完整办法减少总输入量 | 72/72 条完整输入量都低于 `M0`，中位数少 1116.5 | `supported` |
| `P6-C7` | 当前完整办法已经证明对真实模型有效 | `qwen3.8-27b` 完成 216 次自设计题试跑，但完整记录法低于事先要求，完整办法另有 3 次无法解析，最终决定为停止 | `unsupported` |
| `P6-C8` | 对不同模型和不同任务都有效 | 双模型、双任务领域试验没有运行 | `not run` |
| `P6-C9` | 错误再次发生时必须使用专门找回规则 | 相关请求同时触发历史追问，无法单独分清作用 | `unsupported` |
| `P6-C10` | 真实模型小规模试跑的数据和费用记录完整 | 216/216 次正式试验完成，实际用量齐全，请求与结果文件指纹检查通过 | `supported` |
| `P6-C11` | 旧自动判分漏掉了内容正确的答案 | 新版只读复核把 `M0` 的 4 条旧失败全部识别为正确；旧结果文件没有修改 | `supported` |
| `P6-C12` | MemGym-CodeQA 和 SWE-Gym 已经可以正式运行 | CodeQA 正式数据未发布；SWE-Gym 本地仍缺官方数据文件和固定任务编号 | `unsupported` |

前六项只适用于项目自己设计、条件固定的题，不能写成真实编程助手、跨模型或跨任务结论。`P6-C10` 只说明试跑记录完整，不说明办法有效；`P6-C11` 是事后程序诊断，不能替代新数据验证。
