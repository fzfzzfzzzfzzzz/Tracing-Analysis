# 第六阶段：公开测试任务准备说明

这份文档回答现在能否开始准备 MemGym-CodeQA 和 SWE-Gym。最终结果是：本地检查程序和两个固定版本的官方代码仓库已经准备好，SWE-Gym 还缺数据文件，MemGym-CodeQA 的正式数据截至 2026-08-30 仍未公开。本文没有成功下载数据、调用模型、选择正式样本，也没有运行公开测试任务。

## 先说结论

两项准备工作可以与自动判分修复同时进行，但现在不能把它们都算作“已经可以开跑”：

- SWE-Gym 是用真实 Python 项目问题检查编程程序的公开任务。官方数据有 2,438 条，只有一个名为 `train` 的数据划分。项目固定了官方程序代码、官方数据版本以及数据文件的 SHA-256 文件指纹；代码已下载到固定提交，但本机连接 Hugging Face 失败，数据文件尚未下载。
- MemGym-CodeQA 是专门检查长过程里能否记住代码事实的问答任务。官方说明写明正式的 4,289 条数据仍在等待发布审核；现在只有数据说明卡和生成程序。旧 CodeQA、论文里另一批 670 条试验数据以及自行重新生成的数据都不能冒充这批正式数据。
- 默认模型仍是 `qwen3.8-27b`。本次新增程序只计算预计费用，不读取 `.env`，也不发模型请求。

## 本地检查会做什么

命令只在本机完成以下工作：

1. 检查 Git（记录文件版本的软件）中的官方程序仓库是否正好位于固定提交。
2. 检查数据文件的大小和 SHA-256 文件指纹。
3. 读取 `instance_id`，确认同一个任务没有同时进入开发调试和正式验证。
4. 生成输入文件清单、任务编号表、检查报告和各结果文件的文件指纹。
5. 根据任务数、每题比较办法数、每次输入和输出上限计算最高费用。
6. 遇到缺失数据、版本变化、重复任务编号或费用超限时停止。

运行全部检查：

```powershell
python scripts/prepare_phase6_benchmarks.py
```

第一次准备结果已经按“不得覆盖”规则保存。只读查看这次结果：

```powershell
python scripts/analyze_phase6_benchmark_preparation.py
```

只检查 SWE-Gym，并假设先试算 20 个任务的费用：

```powershell
python scripts/prepare_phase6_benchmarks.py --benchmark swe-gym --task-count 20
```

这条命令按当前保守输入设置计算 `20 × 5 × 1 × 55 = 5,500` 次请求的上限，但不会真的发送这些请求。55 是每次任务运行的规划上限：MemGym 官方介绍给出的成对 SWE-Gym 运行约为 110 轮，因此单次运行先按一半估计。按每次最多 50,000 输入 token 和 4,096 输出 token 计算，最高约为 1095.336 元，超过 100 元上限，所以当前配置会停止。

## 现在仍缺什么

- 等 MemGym-CodeQA 官方正式数据发布，然后固定其数据版本和每个文件的文件指纹。
- SWE-Gym 官方程序已经位于固定提交；仍需在网络可用时下载并核对官方数据文件。
- 自动判分修好后，先用未参与修复的数据检查一次。
- 根据新试跑的同题差异估计决定公开任务数量；在此之前不能随意填正式任务编号。
- 分别建立开发调试和正式验证的任务编号文件，保证一个编号只出现一次。
- 根据最终任务数重新核算费用并请用户确认；离线准备不等于已经授权正式运行。

当前配置在 `configs/phase6_benchmark_prepare_v2.json`，格式说明在 `configs/phase6_benchmark_prepare_v1.schema.json`；任务编号划分文件的格式说明在 `configs/phase6_benchmark_task_splits_v1.schema.json`。第一版准备结果错误地把每次任务运行只算成一次模型请求，导致 19.9152 元的旧试算明显偏低；第二版保留第一版结果但明确取代其费用结论。离线检查程序不会调用阿里云百炼，也不会读取保存密钥的文件。
