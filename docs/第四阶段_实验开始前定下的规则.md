# 第四阶段：实验开始前定下的规则

<!-- 大白话说明 -->
这份文档说明第四阶段：实验开始前定下的规则。它记录的是当时准备怎么做、满足什么条件才能继续，不代表所有步骤都已经完成。实际完成情况只看相应结果文档；本文没有新增外部模型调用授权。

> 协议版本：`gdsc_preregistration_v1`
>
> 冻结日期：2026-07-21
>
> 范围：τ³-bench retail / airline development study
>
> 方法：只保留下一步所需信息的办法（第四阶段的记录整理办法）

## 1. 研究问题与证据边界

研究问题是：在不降低任务成功率与 policy compliance 的前提下，能否把不断增长的工具使用记录编译为下一动作所需的最小、可验证决策状态，并显著降低最终 模型服务商 input 与 session 总 token cost。

本轮只使用现有 τ³ retail/airline。它可以支持“τ³ 跨域 development positive evidence”，不能单独支持最终 AAAI 双 benchmark、正式 construct-事先规定的标准答案 或 单独保存的旧记录-recovery 主张。两位独立人工 事先规定的标准答案 和第二 primary benchmark 不在本轮范围。

旧 第一阶段–4 与 `full_ours` 是历史兼容边界：保留原 文件指纹、行为、结果与 停止 解释。旧 Card-only P4 继续或停止条件 既不能替代本协议，也不因本协议被追溯改写。

## 2. 冻结实现身份

- 第四阶段的记录整理办法 记录整理办法：`decision_state_compiler`；
- context policy version：`gdsc_core_v1`；
- 组合 记录整理办法：`acon_official_with_gdsc_state`；
- 工具使用记录之间的关系：原 `TraceGraph` 不可变兼容层，不扩写旧 `NodeType`；
- state layer：独立 `DecisionStateGraph`；
- compiler：hard closure 优先、确定性 beam search、默认 beam width 16、canonical tie-break；
- representations：`RAW_MESSAGE`、`STRUCTURED_STATE_DELTA`、`VERIFIED_SUMMARY`、`NEGATIVE_GUARD`、`ARCHIVE_HANDLE`、`OMIT`；
- omission risk：默认 deterministic safety mask；统计 artifact 只在其独立继续或停止条件通过后启用。

核心接口冻结为：

```text
compile(event_graph, decision_state, query, provider_protocol, budget, risk_model)
  -> PromptBundle
```

`PromptBundle` 必须包含最终 messages/tools、representation 文件清单、closure 来源记录、request 文件指纹、五层成本和 compiler decision log。

## 3. 成本与安全口径

五层成本固定为 graph-selected、compiled、protocol-closed、真正拼成完整请求后的 request 和 模型服务商-actual。真正拼成完整请求后的 request 包含 system、messages、tool schemas 与协议格式开销；模型服务商-actual 仅由 模型服务商 usage 回填。

软实验预算不可行时，编译器返回保留 hard state 的 conservative over-budget bundle，并设置 `matched_budget_eligible=false`。超过 模型服务商 hard context limit 时在调用前中止。不得为了满足预算丢弃 hard fact、关键 policy、未确认的不可逆动作条件或唯一不可恢复证据。

`VERIFIED_SUMMARY` 只从 verified atoms 确定性渲染。`NEGATIVE_GUARD` 只允许来自 schema、policy predicate、环境状态或验证过的替代路径。`ARCHIVE_HANDLE` 在 R4 前只作 来源记录，不计关键证据可见覆盖，也不作恢复效果主张。

## 4. R0：治理、成本审计与开发继续或停止条件

R0 不调用外部模型。必须：

1. 冻结旧 第一阶段–4 artifact 文件指纹；
2. 记录改造前 `117 passed`、ruff 通过的用来比较的办法；
3. 复现 192-view 的 graph-selected / protocol-closed / 真正拼成完整请求后的 cost 错位；
4. 对候选子集计算 模型服务商-token oracle headroom；
5. 生成 claim-evidence 组合实验、eligibility report schema 与本实验开始前定下的规则。

R0 开发 继续或停止条件：成本错位可复现，且至少一个候选子集 模型服务商-token oracle headroom ≥30%。不满足则停止 R1–R4 的实验性推进，并报告测量/benchmark 不适配。

## 5. R1：状态层与 PromptBundle 验收

必须验证：

- 纯 tool-call assistant 也产生 Decision event；
- 相同 截至当时已有的记录 重建得到相同 event/atom/edge/state/request 文件指纹；
- 截至当时已有的记录 后追加未来事件不改变既有 cutoff state；
- reducer 从 neutral 判断记录现在是否还需要 重算且只读 cutoff 内事件；
- conflict、supersession、slot、confirmation、side-effect receipt 均有稳定 来源记录；
- `DecisionQuery` 由 pending operation、retry、tool schema 与 policy scope 确定构造；不确定时保留候选工具而非猜成单工具；
- LLM parser fallback 只能生成低置信 provisional atom；
- pre-send request artifact 与实际发送对象 文件指纹 一致，post-return usage 关联同一 request 文件指纹。

任何未来信息泄漏、随机 ID、hard-state 丢失或 request/文件指纹 不一致都阻止 R2。

## 6. R2：多表示离线机制实验

运行 E1/E4 和 真正拼成完整请求后的 budgets `[2048,4096,8192,12288,16384]`。主预算选择规则：在 hard coverage 100% 的预算中，选择 conservative fallback ≤5% 的最小值；无预算满足则 R2 停止。

R2 继续或停止条件 同时要求：

- structured representation 关键字段等价率 =100%；
- provisional decision sufficiency ≥95%；
- median 真正拼成完整请求后的 marginal cost 相对 Raw 下降 ≥30%；
- protocol、来源记录、coverage、budget 四类 invariant 全部通过；
- 单独保存的旧记录 tamper、非法 Guard、缺失 tool result 等负向 fixture 全部 拿不准时宁可保留或停止。

统计 risk model 使用 task-group held-out split，不得让同一 task/截至当时已有的记录 跨 train/test。启用继续或停止条件为 harm positives ≥20、high-risk recall ≥0.90、ECE ≤0.10 且 Brier score 优于常数用来比较的办法。任一不满足时，R4 继续使用 deterministic safety mask；不得放宽阈值或把训练集指标当 held-out 指标。

## 7. E0：R3 前 benchmark eligibility

任务只依据冻结的结构特征选择，以 task ID 稳定排序，禁止参考 第四阶段的记录整理办法 treatment outcome。retail 与 airline 每域均必须满足：

| 检查 | 阈值 |
| --- | ---: |
| 固定任务数 | ≥10 |
| median agent tool actions | ≥10 |
| dynamic-history decision points | ≥40% |
| 模型服务商-token oracle headroom | ≥30% |
| 判断记录现在是否还需要 现象 | 至少三类、每类 ≥30 decision points |
| snapshot replay | 100% 文件指纹/restore 通过 |
| Full success | 20%–85% |
| native evaluator | 能识别任务成功与副作用 |

先执行 R4 Full 条件首 seed 的 20 sessions，作为 eligibility 与 截至当时已有的记录-capture tranche。任一域不通过完整 E0，则停止，不挑选更有利任务、不降阈值、不增加样本、不进入 R3。

## 8. R3：同一段已有记录 表示干预

从 retail 与 airline 各冻结 15 个 截至当时已有的记录，共 30 个；六类对象各覆盖至少 5 个。每个 截至当时已有的记录 保存 conversation、environment snapshot、工具使用记录之间的关系、DecisionStateGraph、DecisionQuery、tool schema、representation payload 及全部 文件指纹。

冻结设计：

- treatments：Raw / Compiled / Drop；
- replicates：2；
- 总分支：`30 × 3 × 2 = 180`；
- 最多 3 个 agent tool actions；
- temperature=0、并发=1；
- 不自动补跑。

R3→R4 继续或停止条件 是合取条件：

1. treatment 注入与 snapshot/文件指纹 检查 100% 通过；
2. Compiled 模型服务商 input 中位数相对 Raw 至少下降 15%；
3. 无 Compiled 独有 policy violation 或不可逆副作用；
4. representation-induced harm 最多 1/30 截至当时已有的记录；
5. Compiled/Drop 至少 5 个 discordant 截至当时已有的记录，且多数方向支持 Compiled。

安全条件失败、干预未真正进入 prompt 或 discordance 不可识别均立即停止，不运行 R4 剩余矩阵。

## 9. R4：τ³ development 组合实验

冻结样本为 10 retail + 10 airline tasks、2 seeds、4 conditions，共 160 sessions。E0 已运行的 20 个 Full sessions计入总数；通过 R3 后最多再运行 140 sessions。

四条件为：

1. 保留全部旧记录的办法；
2. 文件指纹-必须保留 official ACON；
3. 第四阶段的记录整理办法-Core；
4. official ACON + 第四阶段的记录整理办法 safety/state layer。

agent、user simulator、ACON compressor 均固定 `zai/glm-4.7-flash`；temperature=0、max steps=50、timeout=900 秒、并发=1、run 间隔20秒。native τ³ evaluator 与 trajectory generation 解耦。

外部调用总 cap 为 340 个分支/会话（R3 180 + R4 160，重用的 Full tranche不重复计）。启动时必须重新核验官方免费价格并把来源、时间和估算写入 文件清单。任何非零计费估算、免费额度不足、模型切换/fallback 请求或 cap 超限都在调用前 拿不准时宁可保留或停止。

## 10. 正向判定

只有以下全部成立，才能写“τ³ retail/airline 跨域 development positive evidence”：

- 第四阶段的记录整理办法-Core input/action 相对 Full 至少下降 15%，且配对 反复抽样得到的估计范围 95% CI 上界 `< 0`；
- session total tokens 与净 token cost 均下降；
- success risk-difference 95% CI 下界 `≥ -0.05`；
- policy violation 与 collateral damage 不增加；
- action count、repeated invalid 与 recovery 不恶化；
- 相对 official ACON 存在 matched-cost reliability 或 matched-reliability token 优势；
- retail 与 airline 方向一致。

未满足合取继续或停止条件时，报告对应 停止、负结果或不能否分清各部分作用，不使用“趋势正向”替代实验开始前定下的规则判定。

## 11. 排除、缺失与停止规则

- infrastructure failure 与 agent failure 分开；排除理由必须在看 outcome 前冻结并逐 session报告；
- 无自动补跑；任何人工重跑需新 文件清单、原因和 cap 计算，不得覆盖旧记录；
- 模型服务商 usage 缺失、snapshot/文件指纹 不匹配、treatment 未注入、非实验开始前定下的规则模型均无主结果资格；
- 所有 JSON/CSV/图表只从冻结 artifacts生成；
- 每阶段运行 pytest、ruff、diff check 与 单独保存的旧记录/文件指纹 audit；
- E0、R2、R3 任一继续或停止条件失败时，后续外部矩阵不得启动。
