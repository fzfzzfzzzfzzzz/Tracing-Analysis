# 第五阶段做了什么和得到什么

这份文档说明第五阶段是否能在安全删减旧记录的同时减少完整模型输入量。最终结果是安全检查全部通过，但 185 个可比较时刻中只有 4 个输入更短，同题中位差为 0，没有达到必须小于 0 的条件，所以停止。本文没有运行外部模型，也没有实现下一种结构化整理办法。

> 结果版本：`phase5_liveness_results_v2`  
> F5-G0：通过  
> F5-G1：停止  
> 外部模型调用：0

## 最终决定

第五阶段实现了一个保守办法：先判断当前任务真正需要哪些记录，只删除已经明确结束、完整保存、不会破坏工具调用格式，而且与当前决定无关的整组工具调用。

工程和安全检查都通过，但节省输入量的主要条件没有通过：

- 固定数据共有 261 个时刻，其中 185 个可用于比较成本。
- 只有 4/185 个时刻真正减少了完整输入量。
- “删减后减去完整保留”的同题中位差为 0。
- 实验开始前规定必须严格小于 0。

因此 F5-G1 停止。不能只挑那 4 个有利时刻，不能降低条件，也不能继续实现下一种办法或运行外部模型。

## 程序做了哪些判断

代码中的固定名称保留不变：

- `build_state()`：根据截至当时已有的记录重建状态。
- `derive_roots()`：找出当前目标、限制、确认、未完成操作和证据。
- `analyze_liveness()`：找出当前仍需要的一小段相关记录。
- `project_context()`：只删除确认可以安全拿开的完整工具调用。
- `LifecycleGraphContextManager`：让新办法可以接入旧运行方式。

一组工具调用只有同时满足以下六点才会从当前输入拿开：

1. 与当前决定所需记录没有连接。
2. 组内每条记录都明确已经解决、被替代或使用完毕。
3. 并行工具调用和返回结果完整。
4. 原始工具记录都已按内容单独保存。
5. 保存内容可以重新读取并通过文件指纹检查。
6. 删除后交给模型的工具调用格式仍然合法。

未完成、拿不准、可信度低、涉及规则、确认或操作完成证据、保存原文缺失、返回结果缺失、并行调用不完整的内容一律保留。原始历史本身不合法时，程序拒绝发送，而不是继续删除重要记录。
