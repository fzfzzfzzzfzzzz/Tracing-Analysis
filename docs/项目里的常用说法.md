# 项目里的代码名是什么意思

这份文档只解释项目中已经存在的名称，不创造新的方法名。正文尽量直接说实际动作；只有命令、代码、数据字段和历史编号保留原名。

| 代码或论文里原有的写法 | 普通话解释 |
|---|---|
| `TraceGraph` | 记录每次工具调用、结果以及它们之间关系的程序。 |
| `EventGraph` | 工具使用记录之间的关系。 |
| `lifecycle` | 判断一条记录现在还需不需要。 |
| `PINNED` | 无论如何都必须保留。 |
| `ACTIVE` | 当前任务正在使用。 |
| `DORMANT` | 当前暂时不用，但以后可能要找回。 |
| `SUPERSEDED` | 已经被更新的信息替代。 |
| `EPHEMERAL` | 用完即可丢弃。 |
| `UNCERTAIN` | 现在拿不准，所以先完整保留。 |
| `projection` | 整理后真正交给模型的内容。 |
| `reactivation` | 需要时把旧记录找回来。 |
| `causal closure` | 把与问题相关的前因后果一起找全。 |
| `archive` | 把旧记录单独保存，不放进当前模型输入。 |
| `handle` | 找到某份已保存记录所用的编号。 |
| `protocol closure` | 确保工具调用和它的返回结果成对出现。 |
| `prefix` | 截至某个时刻已经发生的全部记录。 |
| `fork` | 从同一段已有记录开始的不同后续。 |
| `gold` | 实验开始前人工规定的标准答案。 |
| `manager` | 决定哪些记录进入模型输入的整理办法。 |
| `baseline` | 用来比较的办法。 |
| `ablation` | 去掉一个功能以后再比较。 |
| `gate` | 满足才能继续、不满足就停止的条件。 |
| `provider` | 提供模型调用服务的公司或平台。 |
| `serialized tokens` | 把系统说明、消息和工具说明真正拼好后的完整模型输入量。 |
| `provenance` | 一个结论或文件来自哪里。 |
| `manifest` | 一次运行包含哪些文件的清单。 |
| `bootstrap` | 反复抽取同一批题，估计结果可能落在哪个范围。 |
| `Holm` | 同时比较多项结果时使用的一种标准校正办法。 |
| `GDSC` | 第四阶段代码里的方法名；实际作用是只保留下一步需要的信息。 |
| `Failure Card` | 把失败原因和避免办法写成一小段提醒。 |
| `ACON`、`AgentDiet` | 外部公开的记录压缩办法名称。 |
| `τ³-bench` | 一个公开的工具调用任务测试集。 |
| API | 程序之间发送请求的接口。 |
| SHA-256 | 给文件计算指纹的标准办法。 |
| token | 模型计算输入长度和费用时使用的单位。 |
