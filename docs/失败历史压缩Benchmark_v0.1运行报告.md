## 验收结果

下表采用保留原始答案、经持久化账本修复请求副本后的评分。原始评分另行完整保存，修复详情见下一节。

| 门禁 | 结果 | 判定 |
| --- | --- | --- |
| oracle / 无关对照同尺寸 | 56/56 组本地 token 和 provider 首次输入 token 均相等 | 通过 |
| 完整历史审计通过率 ≥95% | 14/48，29.17% | 未通过 |
| 请求与响应哈希完整性 100% | 修复副本 100%；原始 episode 为 92.65% | 修复后通过 |
| provider usage 覆盖率 100% | 100% | 通过 |
| 结构化输出覆盖率 100% | 177/272，65.07% | 未通过 |
| 删除失败链使通过率下降 ≥30 个百分点 | 29.17 个百分点 | 未通过 |
| oracle 恢复 ≥80% 的删除损失 | 9/14，64.29% | 未通过 |
| R1/R2 中位额外调用或 token 减少 ≥50% | 工具调用减少中位数 50%；仅 2 个有效上界 | 数值通过，样本极少 |
| 实际未授权副作用为 0 | 0 | 通过 |

输出状态为：177 个结构化完成、85 个结构化失败、10 个达到轮数上限。85 个结构化失败中，39 个响应的结束原因为 `length`，46 个为 `stop`；不能把所有格式错误都解释成截断。

重获门禁的机器字段为 1.0975865687：实现取“调用减少中位数”与“正额外 token 的减少比例中位数”的较大值。只有一个案例具有正额外 token，且 oracle 比完整历史还少用 token，因此该比例超过 100%。它不是跨 R1/R2 的普遍节省率，也不是总分。

全矩阵的 48 个审计问题中有 34 个完整历史上界失败；8 个交互问题中有 6 个上界失败。这些组合保留在报告中，但排除出压缩伤害分母。

## 请求记录问题及无推理修复

原始运行暴露了一个多轮记录缺陷：请求体浅拷贝共享了工作消息列表，后续追加工具消息时，部分 episode 内嵌的早期请求也被修改了。

核对结果如下：

- 321 条调用前 attempt 与调用后 ledger 一一对应；它们的请求、响应哈希全部有效。
- 20 个 episode 中的 59 份内嵌请求体受影响；实际发送记录仍在已持久化账本中。
- 修复器只允许用两个持久化日志共同证明的快照替换内嵌请求体。响应、哈希、usage 或其他调用元数据不一致时拒绝修复。
- 修复输出到新目录，原始文件不动，模型请求新增 0 次。
- 逐行比较 272 条评分，唯一变化是 20 条 `request_response_integrity` 标志。答案、通过率、因果遗漏、重获调用、token、延迟和费用都未改变。

代码现在为每轮请求创建独立快照，并添加多轮回归测试。修复工具为 `scripts/reconcile_compression_audit_recordings.py`。这一修复没有消除其他未通过的门禁。

## 真正包含失败链的旧数据子集

24 个旧前缀中只有 F1/F2 的 8 个具有完整“失败 → 切换 → 成功”链。其余 16 个是目标恢复、过程解释、状态替换或副作用审计；给它们套用失败问题存在前提不适配。不能把这些兼容资产当成 24 条完整失败轨迹，更不能把 72 个 fork 当成独立样本。

在这 8 个前缀、16 个审计问题上，诊断计数为：

| 条件 | 通过 / 问题数 |
| --- | ---: |
| 完整历史 | 11/16 |
| recent masking | 5/16 |
| 删除失败链 | 0/16 |
| 同预算 oracle | 12/16 |
| 等长无关内容 | 0/16 |

完整历史答对的 11 个问题中，oracle 恢复了 9 个删除损失，无关对照没有恢复。这个小样本支持继续研究该机制，但完整历史本身只有 68.75% 通过率，仍不满足 95% 门槛。

一个具体的 R1 例子是 `legacy:F1_shell_switch:small_cheap`：删除条件相对完整历史多用 1 次模型请求、1 次日志读取、902 个输入 token 和 51 个输出 token。oracle 不需要读取日志，总模型 token 为 1,926，而完整历史为 2,019、删除条件为 2,972。这是受控例子，不能外推为真实编程任务的平均节省。

## 尚不能发布 v1.0 的原因

1. 本轮机制验收没有通过，需要先修订并预注册诊断样本适用范围和输出协议；不能看到结果后调低门槛。
2. 尚无 100 条双人独立标注并仲裁的真实失败链，也没有 60 条经过验证的真实 Docker 回放。当前本机 Docker 客户端存在，但 daemon 未运行；公开数据下载遇到连接超时。
3. 正式真实交互执行接入及 ACON 等正式基线尚未完成实测。当前 fixture 不能替代真实环境回放。
4. OpenHands 轨迹的再分发许可仍待单独核对。冻结配置曾沿用 SWE-Gym 任务数据的 MIT 字段，最终默认配置已改成 `unverified`；本轮未使用或分发该真实轨迹包。

人工材料按[真实轨迹标注指南](失败历史真实轨迹标注指南.md)提供。未得到新试验安排前，不自动发起下一轮付费请求。
