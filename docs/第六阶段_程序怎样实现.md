# 第六阶段：程序怎样实现

这份文档说明代码怎样判断哪些旧记录暂时不用，以及以后怎样找回。最终本地实现通过了全部安全检查和 72 种固定情况。这里描述的本地实现检查没有调用真实模型，也没有改动第一至第五阶段的旧结果；后续另行授权的试跑见[第六阶段真实模型小规模试跑结果](第六阶段_真实模型小规模试跑结果.md)。

## 程序分成哪几部分

```text
原始工具使用记录 + 当前目标
  -> 判断每条记录现在是否需要
  -> 保留当前必需内容，把其余旧记录单独保存
新问题
  -> 判断是否需要找旧记录
  -> 找到最相关的旧记录
  -> 补齐相关前因后果
  -> 补齐工具调用与返回结果
  -> 生成本轮模型输入
```

代码中的固定名称如下：

- `goal_lifecycle.py`：六种记录用途、五种处理方式、当前目标和稳定文件指纹。
- `reactivation.py`：判断为什么要找旧记录，并做关键词查找。
- `causal_projection.py`：沿已有关系补齐前因后果。
- `phase6_scenarios.py`：生成 24 段已有记录、72 种后续和独立标准答案。
- `phase6_experiment.py`：运行 `M0` 到 `M5` 以及七项去掉功能的比较。
- `phase6_metrics.py`：汇总完成率、输入量和反复抽样范围。
- `phase6_gates.py`：判断是否满足继续条件。

## 安全规则

- 一组工具调用中只要有任何内容必须保留、当前要用或拿不准，整组完整保留。
- 工具事件没有可以核对的保存原文时，按拿不准处理。
- 决定收起什么时只能看截至当时已有的记录。
- 同一段已有记录的三种后续必须得到相同收起文件指纹。
- 被新信息替代的旧值找回后只能标作过去事实。
- 工具调用与返回结果必须成对进入模型输入。
- 本地代码把外部模型请求数固定为 0。

## 怎样运行

```powershell
$env:PYTHONPATH='src'
python scripts/run_phase6_controlled.py --config configs/phase6_controlled_v1.json
python scripts/analyze_phase6_controlled.py --input outputs/phase6/e1_controlled_v1
```

生成命令发现目标目录非空时会拒绝覆盖。现有正式结果已经生成，只应使用第二条只读检查命令。

实际数字和不能外推的边界见[第六阶段自己设计的测试结果](第六阶段_自己设计的测试结果.md)。
