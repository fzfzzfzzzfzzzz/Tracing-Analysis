## 服务器执行入口

安装项目和所需本地依赖：`uv sync --extra server-eval`。vLLM、模型权重和 Docker
镜像由服务器部署时准备；此命令不安装或启动推理服务。

`scripts/serve_eval_model.sh` 要求显式提供 `MODEL_PATH`、`SERVED_MODEL`、
`TOOL_CALL_PARSER`、`DTYPE`、`QUANTIZATION`、`LAUNCH_RECEIPT`。
它以新文件保存实际启动 argv。`QUANTIZATION=none` 表示明确不量化。
准备 runtime spec JSON，字段为 served_model、weights_revision、server_version、
dtype、quantization、tool_call_parser、launch_argv、hardware；随后生成完整文件指纹：

```bash
python -m tracegraph.benchmark.server_eval record-runtime \
  --spec runtime.spec.json --weights /models/weights \
  --tokenizer /models/tokenizer-only --output runtime.receipt.json
```

使用原有 `bind-model` 参数加 `--runtime-receipt runtime.receipt.json` 绑定每个模型，
逐次写到新配置。embedding 配置需填写精确模型 ID/revision、地址、返回标识白名单、
维度、上下文上限和 tokenizer 文件清单。缺失配置会阻止 live。
部署 receipt 是操作方记录与文件核验，不代表程序能远程证明 GPU 内实际加载的每个字节。

```bash
python -m tracegraph.benchmark.server_eval prepare \
  --config bound-extended.json --dataset data/server_eval --output prepared-server
python -m tracegraph.benchmark.server_eval run \
  --prepared prepared-server --dataset data/server_eval --output run-server \
  --mode live --execute
python -m tracegraph.benchmark.server_eval score \
  --prepared prepared-server --run run-server --output rescored-server
```

先检查 `preflight.json` 和 `request_recipes.jsonl`。live 内部仍先运行裁判和模型校准，
失败不扩展该模型/预算单元。未知 usage、网络结果或中断中的 job 不自动重发。
自托管 API 无 token 标价不等于硬件成本为零。原 100 元 Flash 费用门槛和旧结果不变。

## 指导词调参和外部数据

```bash
python -m tracegraph.benchmark.server_eval tune-prepare \
  --config bound-extended.json --dataset data/server_eval --output guidance-plan
```

分别使用常规 `run` 执行 `guidance-plan/original`、`evidence`、`causal`，输出到
`guidance-runs/` 同名子目录。然后 `tune-select --plan guidance-plan --runs guidance-runs
--output selected-guidance.json`。只接受同配置、校准通过、全部完成的真实开发运行。
选择规则为全体问题 hard pass 最大、再以部署 token 较低者优先。选择不构成独立验证。

`review-export --dataset ... --output ...` 输出评分草稿和待办；本次没有人工标定。
外部 rubric 的 `causal_mode=partial_order` 需为每个证据集合提供
`causal_paths=[{"evidence_ids":[...],"constraints":[[前因ID,后果ID],...]}]`。
在配置 `data.rubrics` 中填写 `path` 和 `sha256`。

`import-data --source ... --rubrics ... --provenance ... --exposure ... --output ...`
导入完整外部集合。每个 provenance 行包含 prefix_id、prefix_hash、source_task_id、
source_kind；真实 checkpoint 声明还需 checkpoint_path、checkpoint_sha256。
暴露清单为 JSONL，各行包含 public_content_hash。程序不把改名后的已暴露内容当留出集。
导入源须使用项目数据格式，提供 public/prefixes.jsonl、public/queries.jsonl、
private/all_gold.jsonl 和经过项目文件清单校验的 manifest。

纯外部集合可通过 `data.calibration_dataset={"path":...,"manifest_sha256":...}`
另接已有开发校准数据；两个来源不能复用 prefix ID。非开发评估还必须固定
`data.prefix_ids` 和 `data.exposure_manifest`。达到 100 个来源任务只是数量门槛，
并不自动设置 independent_validation 或 human_validated。

## mini-swe-agent 真环境轨道

任务 JSONL 每行要求 id、task、system_prompt、image、cwd、max_model_calls、
evaluator_command、state_contract；可选 env、user、tool_timeout、wall_seconds。
image 必须是已安装镜像的 sha256 标识；不自动拉镜像，不给网络或宿主工作区挂载。
system_prompt 必须规定每次一个 bash 代码块，完成时打印
`COMPLETE_TASK_AND_SUBMIT_FINAL_OUTPUT` 首行及最终文本。
evaluator_command 只在 Agent 结束后执行，不进入 Agent 提示词。

```bash
python -m tracegraph.benchmark.server_eval mini-prepare \
  --config bound-extended.json --tasks real-tasks.jsonl --output mini-plan
python -m tracegraph.benchmark.server_eval mini-run \
  --prepared mini-plan --task-id TASK_ID --model-id qwen38_14b \
  --method tracegraph_0_4 --budget 1536 --calibration run-server \
  --output mini-result --execute
```

`state_contract` 必须为 `filesystem_and_explicit_env_no_background_services`。
Docker commit 不保存进程内存、后台服务或外部数据库；含 volume 的镜像会被拒绝。
因此目前支持可在新 shell 中继续的文件任务，不宣称实现任意环境的进程级快照。
真实轨道报告任务测试结果和实际调用，不与不可变 fixture 的延迟混作真实调查耗时。

恢复传 `--restore 旧目录/checkpoint-....json`，其余配置保持相同，输出指向新目录。
只能从最后闭合边界恢复，原调用账本会继承；不能重跑已完成任务或未知状态请求。
`export-mini-trace --run ... --output ...` 输出未标注公开事件，不捏造失败链或 gold。
导出中的 R0 只是格式占位，必须按 annotation_workitem 完成外部标注后才能进入评估。
