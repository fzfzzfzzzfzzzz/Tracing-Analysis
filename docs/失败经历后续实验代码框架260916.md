# 失败经历后续实验代码框架（260916）

## 目标

在正式人工标注完成前，先固定后续实验需要的软件接口、错误分层和行为指标。当前框架只在合成或开发数据上验证；不会生成、推断或查看 validation/test 金标，也不会发起模型调用。

研究流程被拆成两条可独立运行的链：

1. **保真链**：失败 episode 构建 → 预算内证据选择 → 答案引用 → 语义正确性 → 输出协议。
2. **效用链**：固定任务检查点 → 注入一种记忆条件 → 继续执行 → 统计重复失败、重新探索、成本和任务成功。

## 已实现接口

### 分层保真诊断

`tracegraph.benchmark.failure_experience.diagnose_preservation()` 接收：

- `failure_episode_gold_v1`；
- 自动建链得到的 episode 事件与边（可选）；
- 方法实际放入上下文的事件；
- 模型答案引用的事件顺序；
- 独立的语义和协议判定。

输出分别保存 construction、selection、answer、semantics、protocol 的结果，并给出 `first_failure_stage`。因此总分下降时可以区分：

- 图或 episode 没建出来；
- 已建出但预算内没有选对；
- 上下文正确但模型漏引或倒序；
- 证据正确但语义回答错误；
- 内容正确但输出协议失败。

### Oracle 门禁

`OracleGateThresholds` 不提供隐含默认值。正式 validation 运行前，必须显式冻结最小案例数、上下文证据路径通过率、答案证据路径通过率、语义通过率、协议有效率和可发送率。

`evaluate_oracle_gate()` 只聚合已有诊断，不修改答案或评分。Oracle 未通过时，主方法矩阵不得被解释为记忆方法比较。

### 继续执行评测

`ContinuationTrial` 以 `(task_id, checkpoint_id)` 为配对单位，统一记录：

- task success；
- attempted action keys；
- known failed action keys；
- reacquisition/tool/model calls；
- input/output/observation tokens；
- latency 和 steps to resolution。

`summarize_continuations()` 输出每个方法和记忆条件的成功率、重复失败率、平均重新获取次数、调用数、token、时延和恢复步数。

预先定义的干预条件为：

1. `no_memory`
2. `success_only`
3. `failure_outcome`
4. `failure_reason_and_success`
5. `structured_failure_episode`
6. `full_history`

这些条件只是实验身份；当前代码不会在没有人工 gold 时自动制造对应内容。

## 已加入的结构对照

服务器方法注册表新增两个开发期方法：

- `bm25_pair_window_archive`：BM25 命中后加入完整调用/返回以及前后一个协议单元。
- `bm25_episode_archive`：使用与 TraceGraph 相同的公开、保守恢复链推断，将推断出的 failure episode 作为检索单元，但不做图遍历或依赖闭包。

二者均只读取公开 prefix 和未来允许公开的查询，不读取 gold。第二个对照用于判断收益来自图扩展，还是来自更合理的失败 episode 打包单位。

旧版 `compression_audit_v0_2` 的冻结方法集合没有改变；新增方法只进入新的 server-eval 配置，避免改变旧实验的 episode 数量和历史结果身份。

## 人工标注完成后的接线顺序

1. 将裁决后的 `failure_episode_gold_v1` 导入冻结 dataset。
2. 在 report/postprocess 中把 bundle 的 `visible_event_ids`、答案证据 ID、语义裁判和协议状态传给 `diagnose_preservation()`。
3. 自动建链评测额外传入候选 episode 事件和边；没有这一输出的方法将 construction 标为未评估，而不是失败。
4. 在 validation 上用预注册阈值运行 Oracle gate。
5. 门禁通过后才运行多预算方法比较。
6. 从安全 checkpoint 分支运行六种继续执行条件；同一 checkpoint 的各方法必须共享环境、任务状态、模型设置和调用上限。

## 当前边界

- 尚未设置正式 Oracle 阈值；阈值应在查看 validation/test 结果前登记。
- 尚未把新诊断自动写入现有 server report；这是有 gold 后的接线工作，不妨碍接口和合成回归。
- `bm25_episode_archive` 只使用当前保守的显式 decision＋同目标重试模式，因此它也能暴露自动 episode 推断覆盖不足的问题。
- 继续执行框架目前负责规范化和汇总结果；实际容器分支继续复用现有 `server_eval.mini` 检查点机制。

递归记忆更新、版本链和回滚层已经在 `tracegraph.benchmark.recursive_memory` 中单独实现，设计与剩余接线任务见《有界递归记忆改进框架260916》。
