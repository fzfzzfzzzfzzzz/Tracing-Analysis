# v0.2 开发闭环：实施与离线验收

本轮落实 `pro建议260912.md` 的第一轮安排：评分闭环、正式 TraceGraph 0.4 接入，以及单模型失败归因实验准备。答题和裁判均固定为 `qwen3.8-flash`。本轮没有人工标定，也没有付费授权；本地夹具输出不能作为真实模型成绩。

## 已实现的边界

- 四字段 `a/e/t/s` 从请求、解析、离线夹具到评分贯通。旧十三字段只走 v0.1 兼容评分，混合协议不能合并评分。
- 硬检查负责动作、参数、错误签名、证据可见性与相关性、因果顺序、当前/历史范围和副作用；裁判单独负责必要事实、遗漏、矛盾。无法可靠提取的值保留为待复核。
- 参数优先采用答案中的带标签 JSON 原文；裁判提取必须提供可验证的 Unicode 原文位置，不能复制 gold 来填答案。
- 每题独立 rubric 包括必要事实、矛盾事实、替代证据集合及因果约束。标准答案和规则文件只交给组织者及裁判，不交给记忆方法或答题模型。
- 四种方法为 `full_history`、`recent_masking`、`flat_bm25_archive`、`tracegraph_0_4`。最后一种实际调用 `GraphConstrainedPolicy.snapshot/materialize`，不调用同名参考实现。
- 从公开事件构图，只认可调用配对和明确给出的关系。当前受控开发集没有完整的公开因果边，不能根据 gold 或“后来有成功”补图；这可能限制正式 policy 的表现，须通过实验辨别。
- 两种档案方法使用相同原始档案权限，建档保留预算 768，最终历史预算 1536。masking 使用 1536；Full 保留完整历史。包装标记也计入历史预算，超预算或因果闭包无法装入时标记不可发送，不截断后伪装成功。
- 真实 API 输入量、输出量、构建与检索开销、工具观察量、格式修复和裁判费用分别记录。裁判不计入方法部署成本。

## 冻结的实验安排

实验配置：`configs/compression_audit_v0_2_pilot_qwen38_flash.json`。种子为 20260912。
`compression_audit_v0_2_pilot.json` 保留为没有 tokenizer 的离线工程模板。

|部分|前缀安排|episode 数|
|---|---|---:|
|模型校准|8 个，每个重获等级 2 个；Full 三类问题、oracle 两类历史问题|40|
|主实验|24 个不同前缀；失败原因、完整链、当前状态 × 四方法|288|
|诊断对照|从主实验预选 8 个；删链、oracle、等长无关内容|24|
|交互子集|同一预选 8 个 × 四方法|32|

校准和主实验的源前缀不重叠。选样只使用开发集，按长度、领域、失败类型和重获等级平衡，不能根据输赢换题。现有开发集仅有 **两种失败类型**；本轮不借用 validation/test 的新类型扩大适用范围。

裁判共有 80 条规则样例，40 条开发、40 条验收，两个分组的源前缀也不重叠。样例覆盖正例、错误原因、矛盾、漏证据、无关及不可见引用、顺序错误、动作错误和时态错误。裁判验收至少 36/40 正确，关键误通过为 0；本轮称为“规则样例校准”，不称为人工校准。

模型校准要求首次格式合法至少 36/40、修复后至少 38/40、Full 综合通过至少 20/24、oracle 至少 14/16。裁判或模型校准失败即停止后续 live 工作。离线模式仅为贯通所有分支而运行全部 384 条，不能将其夹具门槛结果用于开放 live。

审计每题最多两次答题调用，其中最多一次格式修复；交互每题最多四次答题/取证调用，修复占用同一限额。另为每条合法提交保守预留一次裁判调用。总请求上界 1298，包含 80 次裁判样例调用和 2 次预检余量；余量不会自动变成额外重试。

## 费用与尚未完成的真实验证

北京地域官方模型页在 2026-09-12 的标价为输入 0.8 元、输出 2.7 元/百万 token。每次请求输入硬上限 65536、输出上限 2048；全部调用都达到上限的保守费用为 **75.2300032 元**，低于规划的 100 元上限。这是标价上界，不是实际账单，也不是授权。

来源：[阿里云 qwen3.8-flash 模型说明](https://help.aliyun.com/en/model-studio/qwen3-8-flash)。执行当天必须刷新价格和授权日期。

已根据 [Qwen 官方发布说明](https://qwen.ai/blog?id=qwen3.8-flash-next) 中的模型与托管 API 对应关系，固定 `Qwen/Qwen3.8-Flash-Next` 的发布 tokenizer，仓库 revision 为 `de4b8e4d43b917e7706784d8bb445c9af86a3540`，文件 SHA-256 为 `0997f410c57a1f4e53b09e4be8f4a172d90edd9564368fb0847030937229b9f3`。对应依据存入 `configs/qwen38_flash_tokenizer_evidence_260912.json`。

这里验证的是官方模型对应关系和规范化上下文的本地计数口径，**没有声称与服务端聊天模板或计费 token 完全相等**；实际 usage 仍单独记录。8 组 oracle/无关对照已同时验证上下文与完整序列化请求等长。普通空白填充只保证第一项，因此新匹配器在无关记录中使用中性词和引号调整两层序列化长度。

live 同时要求：

1. 固定 tokenizer 文件 SHA-256、模型 ID、来源，以及单独保存并校验哈希的官方模型对应依据。
2. 使用冻结计数器的独立准备目录，严格核验 oracle/无关对照的上下文及完整请求等长。
3. 冻结当天价格、明确授权 ID 与日期，并在 CLI 显式提供同一授权 ID。

不满足时停在准备阶段。缺少 usage、网络状态不确定、未完成的已计费 job、费用或输入上限不足都会停止；不会自动重发。并发运行由独占锁阻止，续跑只从已完成 job 的边界开始。

## 本地复现

以下命令全部不调用外部模型，输出目录已存在时拒绝覆盖：

```powershell
.venv/Scripts/python.exe scripts/fetch_development_tokenizer.py --config configs/compression_audit_v0_2_pilot_qwen38_flash.json
.venv/Scripts/python.exe -m tracegraph benchmark-pilot-prepare --config configs/compression_audit_v0_2_pilot_qwen38_flash.json --dataset outputs/compression_audit/v0_1_handoff --output outputs/compression_audit/v0_2_pilot_prepare_260912_r2
.venv/Scripts/python.exe -m tracegraph benchmark-pilot-run --prepared outputs/compression_audit/v0_2_pilot_prepare_260912_r2 --dataset outputs/compression_audit/v0_1_handoff --output outputs/compression_audit/v0_2_pilot_offline_260912_r2 --mode offline
.venv/Scripts/python.exe -m tracegraph benchmark-score --dataset outputs/compression_audit/v0_1_handoff --run outputs/compression_audit/v0_2_pilot_offline_260912_r2 --output outputs/compression_audit/v0_2_pilot_rescore_260912_r2
```

准备目录包含样本分组、384 条首轮请求、rubric、80 条裁判样例、费用预检和文件哈希。运行目录包含中文报告、逐题 CSV、原始模型调用、工具调用、判分、配对诊断和分阶段成本。真实运行才会生成 provider 请求/返回账本；离线结果没有真实 usage。

`benchmark-score` 对 pilot 结果自动使用独立 v0.2 重评分，不再调用模型。它核验数据、run 和 rubric 的身份，输出到新目录。报告同时呈现全体成绩和 Full 答对子集的覆盖率，Full 只称为信息完整参考。

## 验收与下一步

新增测试使用本地模拟响应验证正常提交、格式修复、四轮取证、禁止工具、裁判校准失败、模型校准失败、费用上限、未知请求状态、续跑和独立重评分。最终全仓 360 项测试及 11 项子测试通过；总行覆盖率 85.77%，原发布重点模块均达到 90% 门槛。`release` 在包含当前源码的临时干净快照中通过。原工作区保留未提交改动和用户原文件，未为了通过检查而提交或移走它们。

原有 v0.1 产物、历史阈值和停止结论保持冻结。新输出始终为 `development_only=true`、`independent_validation=false`。本轮真实模型校准尚未运行，不能由离线分数决定算法改进，也不能宣称图结构已优于平面检索。

最终准备、离线运行与独立重评分目录均采用 `_260912_r2` 后缀：384 个 episode，真实请求 0，重评分报告完全一致。8 组大小对照同时等长，最大首轮请求保守输入上界为 22836 token；预检只剩新授权。发布日志与验收摘要保存在 `outputs/compression_audit/v0_2_pilot_verification_260912_r2/`。
