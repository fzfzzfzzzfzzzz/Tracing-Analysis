# Qwen3-14B 裁决后 Oracle-4096 能力归因（260916）

## 结论

本轮完成了 7 个第三模型裁决开发案例的 Full History/Oracle、thinking off/on
配对实验。四个目标 cell 的官方 hard pass 都是 0/7，但不能据此说模型完全没有
能力，也不能启动五方法主矩阵。

主要结论是：**当前 0 分同时由 gold/评分定义和模型能力造成，且前者足以把已有的
部分能力压成 0。** thinking-off Oracle 在 7/7 案例中都覆盖了失败调用、失败结果、
替代调用和成功结果这四类核心事件；其中 5/7 的语义内容也通过 judge。它仍然全部
hard-fail，原因是严格指标要求引用唯一、完整且无额外事件的 gold 集合。相反，两个
案例确实存在语义混链，thinking-on 还存在真实轨迹上的输出协议不稳定，因此也不能
只改评分后就宣称模型已合格。

按照 `pro建议260912.md` 的决策树，这属于“Full 与 Oracle 都 fail，但分项揭示 gold、
题面、协议和模型混杂”。下一步应先修 benchmark 有效性并零调用复算，不应立即跑
BM25、rolling summary、TraceGraph 等主矩阵。

## 目标结果

“核心链覆盖”是诊断性敏感度分析：只要求覆盖 failed call、failure result、
replacement call、success result；它不是事后替换的正式主指标。最后一列还要求
内容 judge 与协议均通过。

| 模式 | 条件 | hard pass | 协议有效 | 内容通过 | 核心链覆盖 | 核心链+内容+协议 | 证据 recall | 因果约束率 |
|---|---|---:|---:|---:|---:|---:|---:|---:|
| thinking off | Full History | 0/7 | 7/7 | 3/7 | 3/7 | 3/7 | 0.679 | 0.536 |
| thinking off | Oracle | 0/7 | 7/7 | 5/7 | 7/7 | 5/7 | 0.867 | 0.807 |
| thinking on | Full History | 0/7 | 3/7 | 3/7 | 3/7 | 3/7 | 0.324 | 0.271 |
| thinking on | Oracle | 0/7 | 6/7 | 5/7 | 5/7 | 4/7 | 0.768 | 0.714 |

Oracle 相对 Full History 的改进很大：thinking off 的证据 recall 增加 0.187、因果
约束率增加 0.271；thinking on 分别增加 0.444 和 0.443，协议有效从 3/7 恢复到
6/7。这说明 9,817-token 平均完整历史并不是性能上界，减少干扰本身有价值。

thinking 没有带来收益。Oracle 的“核心链+内容+协议”从 off 的 5/7 降为 on 的
4/7；Full History thinking-on 还出现 4/7 最终协议失败。当前 Qwen/vLLM 工具提交
组合中，thinking 应视为独立系统因素，不应与记忆方法效果混写。

## 为什么官方结果会全部为 0

### 1. `>=5` 事件约束把辅助证据硬塞进了短链

前三条 Modin 链的事件形状都是：

`先前成功 observation → failed call → error observation → replacement call → success observation`

自然的失败到恢复核心链只有后四项；先前成功的目录 listing 是辅助诊断证据，不是
失败后的因果步骤。它被纳入严格 `ordered_event_ids`，与标注程序要求至少 5 个事件
一致。thinking-off Oracle 三题都只引用后四项，因此各自 recall=0.8、precision=1，
内容正确却 hard-fail。

这表明“至少 5 个事件”不应是 gold 有效性的硬约束。没有独立 decision 消息时，
四事件链是合法结构；辅助前置证据应另列，不应为了长度进入主因果链。

### 2. 唯一精确集合同时惩罚合理漏引和合理多引

thinking-off Oracle 的 7/7 都覆盖四类核心事件，但：

- 5 条漏掉一个 gold 中的前置 observation 或诊断 decision；
- 另 2 条覆盖全部 gold，却分别多引 4 和 8 个相邻记录；
- 因此 7/7 的 `answer_citation_pass` 都为 false。

真实轨迹存在多步调查和多条可支持路径。正式评分应保存核心必需事件、可选支持事件、
人工确认的替代证据集合和因果偏序；证据 precision 与“严格最小链恢复率”可以继续
报告，但不应单独决定所有主通过。

### 3. 两条是真实的语义混链，不是评分假阴性

- `modin-project__modin-6298`：答案的精确动作字段选择了目录 `view_range` 失败，
  语义解释却转去回答任务描述中的 NumPy/NaN 错误；同一答案混合了两条失败链。
- `Project-MONAI__MONAI-4168`：轨迹连续经历缺 `spatial_dims`、`channels`、`strides`
  三次失败。答案选择第一段动作字段，却把后续 `channels`/最终成功混进 switch 与
  resolution；当前笼统题面没有锚定要解释哪一次失败。

这两题说明模型仍有链选择与多失败分段能力不足，同时也说明题面必须提供不泄漏答案的
失败锚点（例如目标调用位置或审计窗口），否则“earlier unsuccessful attempt”在多失败
轨迹中并不唯一。

### 4. thinking-on 在真实轨迹上的协议仍不稳

thinking-on 受控校准为 39/40，但真实 Full History 只有 3/7 协议有效，Oracle 为
6/7。受控校准没有覆盖真实长轨迹下的输出分布。该失败应计入端到端结果，但必须与
检索遗漏、内容错误分开报告。
