## 分组与门禁

校准前缀按 recoverability 分层，并在每层的两个前缀之间做稳定划分。最终 tuning 20 条、holdout 20 条，同一前缀不会跨组，避免同一故障轨迹的信息同时进入调试和验收。

真实答案迁移门禁只看 holdout：

- 有共识的 holdout 必须为 20/20；
- 裁判协议有效至少 19/20；
- 裁判语义结论与人工共识一致至少 18/20；
- critical false positive 必须为 0。

即使门禁通过，导入报告也只设置 `main_matrix_eligible=true`，不会自动执行主矩阵；`main_matrix_authorized` 固定为 false，仍需显式启动授权。

## 如何区分题目问题与能力问题

两位审阅者只根据问题、输入记录、必要事实和真实答案判断每个事实是 `supported`、`missing`、`contradicted` 或 `uncertain`，不查看模型、方法、分组和旧裁判结果。导入后再由组织者解盲：

- 人工认为答案正确，而旧裁判协议失败或判断错误：优先归因于裁判协议/抽取器，不计为模型能力失败；
- 人工一致认为 Full History 或 Oracle 答案缺失或矛盾，且题目与必要事实可从记录直接核验：是模型回答能力或提示适配问题；
- 失败集中在同一题型、前缀或 recoverability，且多种强基线都失败：检查题目、rubric 或输入记录；
- Full History/Oracle 通过而压缩方法失败：才有依据归因于记忆方法。

因此不会再用“全部 0/48”这个单一总分直接判断题目或模型；先分开测量题目可答性、真实答案语义质量、裁判迁移质量和方法差异。

## 审阅流程

1. 两位审阅者只查看 `reviewer_packet/`，分别把 A/B 模板复制到盲审包之外，独立填写全部 40 条。
2. 每位审阅者使用唯一、非空的 `reviewer_id`，把 `human_reviewed` 设为 true，且不得增删或改变 `blind_id`。
3. `contradictions` 中的文本必须逐字出现于 `answer.a`；`overall_semantic_pass` 必须与事实标签一致。
4. 导入两份结果。若有分歧，系统输出空白 `adjudication.template.jsonl`；第三位审阅者只看该模板和原始 `cases.jsonl`，不得看前两人的结果。
5. 导入第三人仲裁结果后重新计算真实答案迁移门禁。

首次导入命令：

```powershell
python -m tracegraph.benchmark.server_eval judge-review-import `
  --packet outputs/server_eval/qwen3_14b_real_answer_judge_review_260913_r1 `
  --reviews <reviewer-a.jsonl> <reviewer-b.jsonl> `
  --output <new-review-result-directory>
```

需要仲裁时，在同一命令中添加：

```powershell
--adjudication <third-reviewer.jsonl>
```

## 实现与验证

- 新增 `judge-review-export` 和 `judge-review-import` 命令；
- 强制真实 live 校准、无 gate override、40 条完整且哈希未变的答案；
- 强制两名不同审阅者、全量逐条标签、精确事实键和矛盾原文校验；
- 分歧未仲裁时，真实答案门禁必定失败；
- 支持只对分歧案例进行第三人仲裁；
- 修复 Windows 下大写文件名导致相同清单被误判的排序问题；
- `tests/test_server_eval.py` 覆盖匿名导出、前缀隔离、双人一致、分歧阻断和第三人仲裁。

正式包自检结果：文件清单有效；40/40 案例与私有映射一一对应；审阅者可见顶层字段未泄露 `episode_id`、`prefix_id`、`query_type`、`method_id`、`recoverability`、`split` 或 `prior_judge`；tuning 和 holdout 的 prefix overlap 为 0。
