# 第六阶段：真实模型小规模试跑开始前定下的规则

这份文档说明真实模型试跑在发送请求前固定了哪些内容。最终试跑已经完成，结论是停止扩大测试，结果见[第六阶段真实模型小规模试跑结果](第六阶段_真实模型小规模试跑结果.md)。这里仍使用项目自己设计的题，不是真实编程任务，也不允许据此直接声称方法已经普遍有效。

## 测试范围

- 从 24 段已有记录中固定选择 12 段，每个场景两段。
- 四种“记录长短 × 重新取得信息的代价”组合各出现三次。
- 每段记录测试继续当前任务、追问旧事和无关新操作三种后续。
- 每种后续比较六种整理办法，共 `12 × 3 × 6 = 216` 次。
- 另做一次最小工具调用检查；只有指定模型确实不可调用时，才允许再做一次备用模型检查。

六种办法是：

| 编号 | 实际做法 |
|---|---|
| `M0` | 所有旧记录一直放在输入里。 |
| `M1` | 只留当前任务和最近两次工具调用，更早内容显示为已隐藏。 |
| `M3` | 按当前目标收起旧记录，但不允许找回。 |
| `M4` | 按当前目标收起旧记录，再按关键词找回。 |
| `M5` | 按当前目标收起旧记录，再把相关前因后果一起找回。 |
| `M6` | 在看到后续问题前，把当前信息和旧信息整理成固定的简短交接记录；不读取标准答案。 |

## 模型和请求

- 首选模型：阿里云百炼 `qwen3.8-27b`。
- 备用模型：`qwen-plus`，只在首选模型不存在、没有调用权限或无法完成最小工具调用时使用。
- 地域：华北 2（北京）。
- 温度：0。
- 思考模式：关闭。
- 每次最多输出 512 个模型输入量单位。
- 每次要求模型调用一次 `submit_answer`，返回答案、依据的记录编号、事实属于现在还是过去，以及是否会重复副作用。
- 不自动重试，避免无法控制请求次数和费用。

模型是否存在和价格在 2026-08-30 从阿里云官方页面重新核对：

- [模型上下架与更新](https://help.aliyun.com/zh/model-studio/newly-released-models)
- [阿里云百炼模型价格](https://help.aliyun.com/zh/model-studio/model-pricing)

北京区公开价格为：`qwen3.8-27b` 输入 3 元/百万、输出 12 元/百万；`qwen-plus` 在本试验的输入长度和非思考模式下，输入 0.8 元/百万、输出 2 元/百万。不假设免费额度或折扣。

## 费用和停止规则

- 用户授权的总费用硬上限是 100 元。
- 最多 218 次请求：一次首选模型检查、必要时一次备用模型检查，以及 216 次正式试验。
- 每次请求的准备阶段输入上限是 50,000。
- 按最贵模型和所有请求都达到上限计算，理论最高费用为 34.039392 元，低于用户授权上限。
- 每次请求前检查剩余额度，每次请求后记录服务商返回的实际输入量、输出量和费用。
- 费用可能超过 100 元、请求数超过 218、文件指纹不符、密钥文件未被 Git 忽略或返回结果不完整时立即停止。

## 继续或停止条件

- 所有旧记录一直保留时，正确率至少 0.95。
- 至少 0.95 的正式试验得到可检查的结果。
- 请求文件指纹和实际用量记录必须完整。
- 按前因后果找回的办法不能出现重复副作用，也不能把旧事实当成当前事实。
- 任一条件失败，结果保留，但结论写成停止，不扩大到公开任务。

第一次最小检查使用 `configs/phase6_live_qwen38_27b_v1.json`。当时程序错误地要求回答必须逐字等于指定短语，把首选模型已经成功返回的工具调用误判成不可用，并额外调用了一次备用模型；没有开始 216 次正式试验。这个问题修正后，正式设置保存在 `configs/phase6_live_qwen38_27b_v2.json`，文件的 SHA-256 指纹为 `81478FF6FA087F23254DF34C08AE70CB41D1715F1D72BDC88A19FCE52BFDCD29`。运行程序是 `scripts/run_phase6_live_pilot.py`；只读检查程序是 `scripts/analyze_phase6_live_pilot.py`。
