# Qwen3.8-27B stock mini-SWE-agent Harness 有效性与三种子结果（260917）

## 结论

旧 TraceGraph MiniModel 的 SWE 结果不能直接解释为模型能力：它把历史扁平化为 JSON，并限制每轮一个工具调用。现已用固定版本的 stock mini-SWE-agent 2.4.6 完成独立对照，原生 assistant/tool 历史和单轮多工具调用均通过探针。

在排除上下文预算与客户端超时诊断轮后，Qwen3.8-27B 在公开的 `pytest-dev__pytest-5221` 上完成 3 个可计分种子，隐藏测试为 **0/3**。这次 0/3 已不能归因于旧 TraceGraph Harness：两个种子正常提交非空补丁但误判输出契约，一个种子因模型连续三次未生成工具调用而被 stock agent 终止。

因此目前最准确的表述是：

- 原 TraceGraph Harness 确有结构性混淆，旧 0 分不能单独证明模型无能力；
- stock Harness 有效且显著改善了行为健康度，2/3 种子能编辑、测试并提交；
- 但 Qwen3.8-27B 在这道已暴露短题上仍未通过，主要剩余问题是精确规格推断和工具协议稳定性，而不是“完全不会使用仓库工具”；
- 单题三种子不能外推为完整 SWE-bench 能力结论。

## 固定实验条件

- 模型：`Qwen3.8-27B-rev-1d4bf0f`，BF16，TP=4，thinking 开启。
- 服务：SGLang 0.5.10，GPU 0–3，64K 上下文，单并发；GPU 4–7 未占用。
- Harness：mini-SWE-agent 2.4.6，源码 revision `a83fcae82d2a08f0ee0c688f9d137b3566c097f8`。
- Agent：stock interactive/yolo，250 step 上限，原生完整历史，不做压缩。
- 单轮输出上限：8192 token；请求超时：600 秒。
- 镜像：固定 `pytest-5221` digest；容器断网、4 GiB、2 CPU。
- 只运行已暴露的 `pytest-5221`；未触碰其余 5 道保护题。

原生协议探针验证了两轮对话中的 `system → user → assistant(tool_calls) → tool → user → assistant(tool_calls)`，两次工具调用均成功解析和执行。

## 三种子结果

| Seed | 终态 | 模型调用 | 工具动作 | 首次编辑 | 非空提交 | 隐藏测试 | 失败归因 |
|---|---:|---:|---:|---:|---:|---:|---|
| 20260917 | Submitted | 36 | 55 | 20 | 是 | 0/2 | 把 scope 放在独立 `scope:` 行 |
| 20260918 | RepeatedFormatError | 8 | 9 | 无 | 否 | 0/2 | 连续 3 次无有效工具调用 |
| 20260919 | Submitted | 47 | 55 | 34 | 是 | 0/2 | 使用 `[scope=session]`，且 verbose 分隔符错误 |

汇总：隐藏测试 0/3；2/3 产生并提交非空补丁；1/3 因工具协议失败终止；总计 91 次模型调用、119 次工具动作，微平均有效工具响应率 83/91（91.2%）。

金标测试要求的关键格式是 `tmpdir_factory [session scope]`，verbose 为 `tmpdir_factory [session scope] -- ...`。两个完成提交的种子都找到了正确实现位置、读取了 `fixturedef.scope` 并运行回归测试，但分别选择了不同的错误展示格式。这是可定位的规格推断错误。

## 排除的诊断轮

三轮预实验不进入成绩：

1. 32K 服务 + 8192 输出预算：第 20 步时输入 26,248 token，总请求 34,440，确定性超过 32,768；无补丁。
2. 32K 服务 + 2048 输出预算：第 39 步输入 30,864，总请求 32,912；已有补丁但提交前溢出，隐藏测试仍因版式错误失败。
3. 64K 服务 + 8192 输出预算 + 180 秒超时：服务仍以约 29 token/s 正常解码时被客户端超时；无补丁。

这些轮次分别归类为上下文预算或请求超时，不计作模型任务失败。最终计分配置改为 64K、8192 输出、600 秒超时。

## 与旧 TraceGraph Harness 的比较

旧基线、guarded 和 stagnation-nudge 三轮均以空补丁和 `RepeatedFormatError` 结束。stock 对照中，两个种子可完成几十次调用、并行/多工具探索、源码编辑、公开测试和正式提交。这证明旧 Harness 压缩了可观察到的模型能力，不能再把旧 0 分写成纯模型能力结论。

但 stock 的三种子仍是 0/3，且两个失败补丁与隐藏契约的差异可逐行定位。因此在这道题上，当前证据支持“模型仍存在能力错误”，而非“只要修 Harness 就能通过”。

## 下一步

1. 冻结本次 stock Harness、64K 服务参数、镜像 digest 和探针作为 SWE 复现基线。
2. 不再继续调 `pytest-5221` 来追求通过率；它已暴露隐藏格式，后续只作为开发诊断题。
3. 从未用于调参的新 SWE 任务抽取小批量复现，先做 5–10 题单种子健康门禁，再决定是否扩展三种子或全量。

5. 在新题上仍保留失败分型：基础设施失败不计分；协议失败、空补丁、错误补丁和测试失败分别统计。
