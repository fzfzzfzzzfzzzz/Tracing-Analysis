## 允许沿用的历史主张

- 第三阶段 P1 的确定性 失败原因和避免办法的简短记录 干预只能作为受控机制证据；其中的本地 真正拼成完整请求后的 token 不是外部 模型服务商 usage。
- 第三阶段/P3b-A 的 trajectory/evaluator 解耦、Failure-chain v2 与 next-3-action 回放是已验证基础设施。
- 旧 Card-only P4 为 停止：token CI、success non-inferiority、Remove 机制和人工 construct 继续或停止条件 未通过。
- 这些历史结论不否定 第四阶段的记录整理办法，也不能当作 第四阶段记录整理办法的正向证据。

## 禁止性解释

- 不把 `117 passed` 写成 R0/R1/R2 实验通过；它只是改造前用来比较的办法。
- 不把 graph-selected、compiled 或 protocol-closed token 降幅写成 模型服务商-actual 节省。
- 不把 模型服务商 单价为零写成 token cost 为零。
- 不用 task selection、阈值下调、追加样本或自动补跑挽救未通过继续或停止条件。
- 不从 offline view 推断 task success、policy compliance 或 collateral damage。
- 不把同模型同会话 Codex A/B 写成两位独立人工 事先规定的标准答案。
- 不把 τ³ retail/airline 两域写成两个独立 benchmark。

继续或停止条件未通过时，应写：

> 在实验开始前定下的规则的 `<stage>` 中，`<metric>` 为 `<value>`，未达到 `<threshold>`，因此停止后续 `<stage>`；未追加样本或调整阈值。
