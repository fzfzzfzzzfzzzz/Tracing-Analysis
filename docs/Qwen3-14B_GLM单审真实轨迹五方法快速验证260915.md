# Qwen3-14B + GLM 单审真实轨迹五方法快速验证（260915）

## 结论

本轮完成了可复现的开发试跑，但不能据此宣称 TraceGraph 优于或劣于其他方法。最终远端 r2 完整运行 166/166 个 episode，339 次 provider 调用全部有有效 usage，`stop_reason=null`。规则门与模型校准门均通过；真实主矩阵的 hard pass 很低，并同时受到金标协议错误、真实链题能力瓶颈和压缩器预算不可行三类因素影响。

当前最合理的下一步不是扩大主矩阵，而是先裁决本轮 7 个已暴露开发前缀，然后用裁决后的 gold 做 4096-token oracle 能力归因。只有 oracle 在真实链题上达到可用水平，五方法主比较才有解释价值。

## 真实主矩阵

| 方法 | hard pass | 实际发送答案的 episode | 主要不可行原因 |
|---|---:|---:|---|
| Full History | 3/21 | 21/21 | 无 |
| recent masking | 3/21 | 21/21 | 无 |
| flat BM25 archive | 3/21 | 10/21 | 原子记录装箱后超过 1536 |
| rolling summary | 0/21 | 9/21 | 4/7 前缀的构建回答被截断 |
| TraceGraph 0.4 | 3/21 | 9/21 | 4/7 前缀的因果闭包/摄取超过预算 |

分题型看，Full History、recent masking、BM25 都只在 failure-cause 上通过 3/7；TraceGraph 在 failure-cause 上通过 2/7、在 current 上额外通过 1/7；所有方法的 chain 都是 0/7。由于只有 7 个前缀，而且三种压缩方法大量未发送，hard-pass 相同不代表方法等价。

Full History 平均上下文 9817 token，21 次主矩阵回答共消耗 218,701 prompt token；recent masking 平均 1294 token，消耗 39,724 prompt token。二者 hard pass 相同，但 recent masking 的证据 recall 相对 Full History 的配对差为 -0.0517，95% exploratory CI 为 [-0.0989, -0.0136]。该结果只说明在当前 7 个开发前缀上压缩减少了证据覆盖，不能推断总体性能。

## 能力与题目归因

1536-token 诊断 oracle 只有 3/7 条完整链能放入预算；这三条在源证据、语义事实和动作参数上都可回答，但 Qwen3-14B 均稳定漏引最前面的“失败 tool_call”事件，只引用失败结果、决定、替代调用和成功结果，所以 0/3 hard pass。删除关键证据的 deletion 为 0/7，符合预期。

更重要的是，Reviewer B 的 86/86 条接受记录都把四个机器精确字段写成了解释性短语或重构参数，而评测题面要求复制源事件的 `tool_name` 与 `content.arguments`。协议规范化后，三条可用 oracle 的精确值全部通过，剩余失败仅为漏引失败调用；主 hard-pass 总数未改变。

Reviewer A 文件已经存在，但同样是 GLM 替代标注。A/B 的一致性不足以支持 gold：

- 双方都接受 80 条；状态不一致 10 条。
- recoverability 仅 37/80 一致。
- ordered evidence chain 仅 8/80 完全一致。
- error signature 仅 14/80 逐字一致。
- 本轮 7 个前缀的 ordered chain 为 0/7 一致，recoverability 有 4/7 不一致。

因此当前成绩至少同时包含：真实链引用对 14B 过难、A/B 标注选择不同、1536 预算不适合若干真实因果闭包。不能把 0 分单独归因给检索算法，也不能把三种 3/21 方法视为打平。

## 已实施修复

1. 单审开发集的四个精确动作字段改为从 reviewer 选中的 source event 自动派生；reviewer 原文本只留哈希审计，不再作为 gold。
2. 正式 v1 gate 新增“精确工具字段必须匹配所选源事件”约束。
3. 新标注包说明明确禁止在精确字段中增加 `tool`、`wrapped_tool`、`_verb` 或把数组改写成字符串。
4. 格式修复提示改为有界文本，不再回显最多 2048 token 的原回答。
5. Full History 冻结预检覆盖首次回答、最坏格式修复、answer 到 judge 的序列化膨胀和 judge 输出。
6. 7 条分歧裁决包生成于 `审阅/adjudication_glmdev260915_r1`。

## 下一步门槛
