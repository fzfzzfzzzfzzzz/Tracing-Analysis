## 评测链路修正

第一次真实请求触发了安全停机：本地 Transformers 5.17 的 `apply_chat_template()` 默认返回 `BatchEncoding`，旧代码将字段数误当 token 数，得到 267 的错误上界，而 vLLM 实际 prompt 为 1536 tokens。

修正为显式 `return_dict=False` 后，同一请求冻结上界为 1801，实际 1536，随后 80 条最终请求的用量、模型名与响应均有效。该兼容性修正有回归测试。

裁判 prompt 还存在“fact ID”歧义：模型最初把 `records[*].record_id` 当作 `necessary_facts` 的键。prompt 已明确两者并通过结构校验；最终 80/80 verdict 均可解析。模型仍将 `claims_to_check` 的候选反事实机械复制到 `contradictions`，即使答案未包含该句，导致系统性假阴性。继续修改评分器或门禁来迁就已看到的结果会构成事后调整，所以没有继续。

相关本地测试最终为 `76 passed`；服务器环境为 `58 passed, 1 skipped`，跳过项是未下载的可选 tokenizer 测试。
