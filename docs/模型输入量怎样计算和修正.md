# 模型输入量怎样计算和修正

<!-- 大白话说明 -->
这份文档说明模型输入量怎样计算和修正。最终数字以及当时的通过、停止或没有运行决定原样保留，没有因为文字改写而改变。本文没有重新运行实验，也没有把证据不足的结果写成已经证明。

## 第四阶段的记录整理办法 v2.0：从内容估算到最终请求责任

`content_estimate_v2` 仍用于旧 工具使用记录关系图 节点与 graph-selected 层，但不能代表 第四阶段记录整理办法的最终 prompt 成本。第四阶段的记录整理办法 对以下五层分别计量：graph-selected、compiled、protocol-closed、真正拼成完整请求后的 request、模型服务商-actual。前三层解释编译过程；离线预算以完整 真正拼成完整请求后的 request 为准；live 效果以 模型服务商-actual 为准。

真正拼成完整请求后的 request 必须覆盖 system、messages、tool schemas 和 模型服务商 协议格式开销，并记录 serializer/tokenizer 版本与 request 文件指纹。工具 schema 不得作为“固定项”从条件差异中静默排除。模型服务商-actual 只接受上游返回 usage；缺失、估补、request 文件指纹 不匹配或将 compressor usage 漏出 session total 都令该样本失去主结果资格。

成本报告至少同时给出：每 action input、session agent input/output、user simulator input/output、ACON compressor input/output、编译本地开销、净 token cost 与 模型服务商 monetary cost。即使价格为零，也必须报告 token cost，且在 live 启动时重核免费价格并冻结证据。

软实验预算与 模型服务商 hard limit 分开：软预算不可行时保留 hard state并标记 `conservative_over_budget=true`、`matched_budget_eligible=false`；模型服务商 hard limit 超出则不得发送。只比较未超软预算样本会产生选择偏差，因此 fallback 率与排除数必须并列报告。

旧结果中的 `estimated_selected_tokens`、`protocol_closed_tokens` 和 `agent_provider_input_tokens` 保持原含义，不追溯改名为上述新层。R0 已对冻结的 192 个旧 `full_ours` context views 完成独立复现：192/192 存在 graph-selected / protocol-closed 错位，中位错位 `42.040%`。旧记录没有 真正拼成完整请求后的 request/模型服务商-actual 字段，因此这两层保持 null，不能从 closure 估算冒充。

## `content_estimate_v2` 历史修正

### 问题

2026-07-16 的工具使用记录审计发现，旧版 τ 导入器曾把 assistant 消息的
`prompt_tokens + completion_tokens` 作为该消息节点自身的 `token_count`。
`prompt_tokens` 包含当轮之前的完整输入历史、系统提示和工具 schema，不是该条
assistant 消息的内容长度。把它写入节点后会重复累计历史，并夸大
ContextView 的预算压力。

一个真实例子中，几十词的 assistant 回复被记为约 5,000 tokens；修正后同一
会话的最终图为 4,676 个内容估算 tokens，而该会话所有 agent 调用的真实累计
模型服务商 prompt usage 为 48,961 tokens。这三者分别表示：

- 节点内容长度：用于图内预算选择；
- 单轮/累计 模型服务商 prompt usage：用于真实 API 输入遥测；
- 模型服务商 completion usage：用于输出遥测。

它们不能互相替代。

## 修正版口径

新版本固定为 `content_estimate_v2`：

1. 所有 工具使用记录关系图 节点的 `token_count` 只对节点自身内容做确定性的
   byte-aware 估算；
2. 模型服务商 的 prompt/output usage 原样保存在节点 metadata 和官方
   simulation 中，不进入节点大小；
3. 在线矩阵把 `token_accounting` 写入 config、plan、run 环境、工具使用记录关系图 和
   ContextView；配置与运行时代码版本不一致时 拿不准时宁可保留或停止；
4. 同题比较 聚合同时报告估算的 selected-context tokens 和真实
   `agent_provider_input_tokens`，效果结论优先参考后者。

## 已有结果的边界

- Stage 1 的官方 reward、termination、工具动作和成本不受该问题影响；
- 30 条 Stage 1 Full-Trajectory 图已用
  `scripts/retokenize_traces.py` 重计量并重新验证；
- Stage 1 中位内容工具使用记录为 `4,875` tokens，仍通过冻结的 `≥ 4,096` 门槛；
- 修正后的预算 sweep 推荐 `4,096`，而不是旧口径下的 `16,384`；
- `g47f_ml_3t1` 的压缩条件实际模型输入受旧预算口径影响，因此只能保留为
  修复前诊断，不能继续作为正式 同题比较 结论；
- `g47f_fr_3t1` 在进入压缩条件前被主动中止，已有 Full-Trajectory 样本只用于
  确认 failure-rich 选择能产生真实 Error，不构成完整矩阵结果。

替代矩阵：

- corrected smoke：`g47f_ml_s3`，8/8 sessions/traces/单独保存的旧记录 已通过；
- corrected 判断记录现在是否还需要 组合实验：`g47f_ml_c2`，120/120 sessions/traces、1,768 个
  单独保存的旧记录 objects 已通过；完整办法 对 保留全部旧记录的办法 的 28 个有效配对成功率
  差为 `+0.1429`，95% CI `[-0.0714, 0.3571]`；
- corrected failure-retention 组合实验：`g47f_fr_c2`。

`g47f_fr_c2` 已完成 90/90 sessions，全部 trace 均记录 `content_estimate_v2`。完整办法 相对 Ours without failure retention 的 同题比较 token 结果为：mean selected-context delta -1,596.1，95% CI [-12,300.2, 8,662.5]；mean actual agent 模型服务商 input delta -1,513.8，95% CI [-24,108.8, 21,278.1]。因此 failure retention 在该矩阵中没有形成显著 token 改善；同时 完整办法 相对 保留全部旧记录的办法 的 selected-context 与 actual-input delta 均为正点估计，说明 failure-rich 长尾任务上当前策略可能带入额外噪声或增加工具使用记录长度。

corrected smoke 的四个条件均成功 1/2，且 8 条工具使用记录全部记录
`content_estimate_v2`、0 graph/单独保存的旧记录/API/参数错误。它还验证了两种输入统计不会
混为一谈：Last-k 相比 保留全部旧记录的办法 每次 agent 调用平均少约 1,356 个真实
prompt tokens，但由于调用次数更多，累计真实输入差为 +1,439。该 smoke 只用于
管线验收，不作效果推断。

`g47f_ml_c2` 的 120 条工具使用记录全部记录 `content_estimate_v2`，模型服务商 input usage
覆盖所有非 timeout 会话。完整办法 相对 保留全部旧记录的办法 的 mean estimated
selected-context 配对差为 `-9,306.2`，95% CI `[-20,662.6, -139.9]`；真实
agent 模型服务商 input 配对差为 `-13,533.7`，95% CI
`[-32,678.8, 2,630.5]`。因此当前可以声称图内选中内容减少，但不能声称真实
模型服务商 输入已显著减少。

## 可复现命令

```powershell
$env:PYTHONPATH = "src"

python scripts/retokenize_traces.py `
  --input outputs/tau3_live/g47f_s1_v1 `
  --output outputs/token_accounting/g47f_s1_v1_repair.json

python scripts/analyze_glm_stage1.py `
  --plan outputs/plans/g47f_s1_v1.json `
  --results-root vendor/tau3-bench/data/simulations `
  --output outputs/stage1_analysis/g47f_s1_v1 `
  --graph-output data/processed/g47f_s1_v1_graphs `
  --archive-output artifacts/g47f_s1_v1_archive

python scripts/run_budget_sweep.py `
  --input data/processed/g47f_s1_v1_graphs `
  --archive artifacts/g47f_s1_v1_archive `
  --output outputs/budget_sweep/g47f_s1_v1_content_v2 `
  --budgets 2048 4096 8192 12288 16384
```

原始 模型服务商 usage、修复报告、raw results、traces 和 单独保存的旧记录 均位于 Git 忽略
目录；公开仓库只保存实现、冻结配置、统计定义和诚实的结果边界。
