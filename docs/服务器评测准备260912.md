# 服务器评测代码与部署步骤

当前阶段只准备代码和离线验证，不启动模型服务，也不发送真实推理请求。
计划使用 Qwen3.8 8B、14B；这两个名称目前只是实验配置位，具体仓库名、权重
revision、量化方式和服务返回名称必须在服务器部署后填写，不能猜测。

## 已固定的执行边界

入口为 `python -m tracegraph.benchmark.server_eval`，独立于旧的固定 Flash pilot。
配置为 `configs/server_eval_qwen38.json`。默认两个模型、768/1536/3072 三个历史
预算、七种方法，固定种子 20260912。统一模型答题循环和四字段评分沿用 v0.2。
全矩阵包含 3744 个任务 episode；另有共享的 80 条规则裁判校准样例。
压缩和恢复产生的额外调用有单独上界，不属于任务 episode 数。

裁判默认固定在 14B 配置位，使用独立请求；模型方法名、其他答案不进入裁判输入。
先完成规则裁判校准，再对每个“答题模型 × 预算”单元进行 40 题模型校准。
失败单元跳过自己的主实验，其他模型仍按固定人口校准，不补题、不换题。
8B/14B 全部就绪后可以一次启动整个矩阵，内部仍按上述顺序执行。

|方法|实际实现与本轮比较口径|
|---|---|
|Full history|完整公开历史；信息完整参考，不受压缩预算约束|
|Recent masking|按最近记录选择，补齐调用与返回|
|Flat BM25 archive|同档案权限的平面检索，k1=1.2、b=0.75|
|TraceGraph 0.4|正式 GraphConstrainedPolicy.snapshot/materialize|
|Rolling summary|逐块滚动生成摘要，构建时没有未来问题；所有压缩调用计入|
|ACON official|固定官方 ObservationOptimizer、HistoryOptimizer 和原始 prompt，通过公开记录桥接运行|
|AMA official BM25 profile|固定官方因果构建/多阶段恢复函数，显式选择上游支持的无 embedding/BM25 配置；最终答题仍走统一 Runner|

这不是声称复现了外部论文的整套系统和原表格成绩。ACON 的原始 prompt 没有在
本数据上优化；AMA 的 embedding 版本没有在此配置中冒名启用。AMA 的上游内部
字符裁剪策略仍属其正式实现，适配器另计真实 token 和最终上下文上限。
所有 profile、上游 revision、文件 SHA 和适配行为写入构建状态。
AMA 工具文件中未使用的分布式 Ray 工具采用模块内延迟导入；同步建档、恢复及
Docker 搜索不需要启动 Ray，官方算法源文件本身没有被修改。

BM25、TraceGraph 档案建档的驻留预算为最终预算一半。AMA 的状态摘要也受此驻留
预算约束，因果图、原轨迹和索引作为档案保存。滚动摘要和 ACON 的最终摘要可用
完整历史预算。任何方法输出超预算会记录不可发送的原因和尝试内容，不在适配层
偷偷截掉证据。AMA 读出的原始证据补齐调用与返回，包装、摘要和证据一起计预算。

AMA 会额外调用模型判断证据充分性，并可能生成搜索代码。默认配置明确关闭代码
执行；遇到 NEED_CODE 分支会记录方法失败，不能把该配置称为完整 AMA-Agent。
需要启用时，在新的配置中把 `ama_code_search.mode` 改为 `docker`，并填写本机已
安装的 Python 镜像 digest（`name@sha256:...`）。代码已经接好这一分支：只挂载
包含公开轨迹的脚本，禁网、只读、非 root、限制 CPU/内存/进程；不会挂载 gold、
凭证或项目目录，不自动拉取镜像。此沙箱只搜索轨迹，不是环境任务的 Docker 回放。
上游代码搜索允许最多三次已知代码错误修正，这些也是独立记账的恢复调用；网络
结果不确定时从不自动重发。

## 本地准备与服务器迁移

在项目根目录，可直接用已有 Python 环境运行以下不发模型请求的命令：

```powershell
.venv/Scripts/python.exe -m tracegraph.benchmark.server_eval fetch-sources --config configs/server_eval_qwen38.json
.venv/Scripts/python.exe -m tracegraph.benchmark.server_eval prepare --config configs/server_eval_qwen38.json --dataset outputs/compression_audit/v0_1_handoff --output outputs/server_eval/prepare_260912
.venv/Scripts/python.exe -m tracegraph.benchmark.server_eval run --prepared outputs/server_eval/prepare_260912 --dataset outputs/compression_audit/v0_1_handoff --output outputs/server_eval/offline_260912
.venv/Scripts/python.exe scripts/package_server_eval.py --dataset outputs/compression_audit/v0_1_handoff --output outputs/server_eval/server_bundle_260912.zip
```

准备阶段冻结的是完整任务清单和请求生成配方。滚动摘要/ACON/AMA 的真实输出
必须在运行后才知道，因此无法提前伪造完整动态请求；每个真实请求体都会在发送前
持久化并计算哈希。构建只接收公开前缀，后续问题和 gold 不传给记忆方法。

打包脚本采用文件允许清单，包含源码、配置、锁文件、测试、数据和已下载的固定
上游源码，生成文件哈希清单；不含模型权重、`.env`、Git 目录或已往评测结果。
将包解压到服务器新目录；运行前校验 `server_bundle_manifest.json` 中所有文件哈希。
也可以直接同步整个代码仓库，忽略 `.env` 和 outputs 中的旧运行目录。

Linux 服务器依赖：

```bash
uv sync --extra server-eval
uv run --extra server-eval python -m tracegraph.benchmark.server_eval --help
```

vLLM 单独按服务器 CUDA/驱动环境安装并固定版本，避免 benchmark 安装器替换推理
服务的 PyTorch/CUDA 环境。`scripts/serve_eval_model.sh` 接收 `MODEL_PATH`、
`SERVED_MODEL`、`TOOL_CALL_PARSER`、端口和并行度等环境变量。未知显卡/权重时不
自动设置设备、不自动下载权重，也不假定两模型能同时驻留显存。14B 被固定为裁判，
需要和当前答题服务同时可访问；如果硬件放不下，先调整部署或另冻裁判配置，不能
在运行中偷偷换模型。

## 绑定两个服务后再冻结正式运行

为每个模型准备一个只含 tokenizer/config/chat-template 文件的目录。绑定命令
保存该目录的全部文件 SHA；使用本地 transformers tokenizer，不允许下载或
`trust_remote_code`。本地历史计数精确；完整请求采用同模板计数并预留传输开销，
服务端实际 usage 单独校验。它不是承诺未知服务聊天模板与本地计费口径相同。

```bash
uv run --extra server-eval python -m tracegraph.benchmark.server_eval bind-model \
  --config configs/server_eval_qwen38.json --model-id qwen38_8b \
  --base-url http://127.0.0.1:8000/v1 --served-model YOUR_8B_SERVED_NAME \
  --weights-revision YOUR_EXACT_WEIGHT_REVISION --server-version YOUR_VLLM_VERSION \
  --tokenizer-dir /absolute/path/to/8b-tokenizer --output configs/server_eval_bound8.json

uv run --extra server-eval python -m tracegraph.benchmark.server_eval bind-model \
  --config configs/server_eval_bound8.json --model-id qwen38_14b \
  --base-url http://127.0.0.1:8001/v1 --served-model YOUR_14B_SERVED_NAME \
  --weights-revision YOUR_EXACT_WEIGHT_REVISION --server-version YOUR_VLLM_VERSION \
  --tokenizer-dir /absolute/path/to/14b-tokenizer --output configs/server_eval_bound.json

uv run --extra server-eval python -m tracegraph.benchmark.server_eval prepare \
  --config configs/server_eval_bound.json --dataset data/server_eval --output runs/prepared
```

`preflight.json` 无阻塞项、确认部署资源和配置后，由使用者显式启动：

```bash
uv run --extra server-eval python -m tracegraph.benchmark.server_eval run \
  --prepared runs/prepared --dataset data/server_eval --output runs/evaluation \
  --mode live --execute
```

这不是此前 100 元 Flash API 授权的延续。新入口只配置自托管服务，没有付费云模型
fallback。请求次数、输入/输出总 token、累计运行时限和单方法阶段调用上限都会
限制运行。硬件/电费未知，不把零 API 标价解释为零部署成本。

`--max-new-jobs N` 在完整 job 边界暂停，之后用同一配置及 `--resume` 续跑。
不确定 usage、超限、网络结果不确定、返回错误模型或尚未完成的已发送 job 都停止。
发生硬崩溃遗留锁时，先确认原进程结束、检查两个 provider 账本和 completed_jobs，
再处理锁；未知请求不能因为删了锁就自动重发。

## 独立数据、输出与证据范围

`data.split` 可设为 validation/test，必须同时提供事前选好的 `prefix_ids` 和
此前已接触样本的 `exposure_manifest`（JSONL，每行 `public_content_hash`），程序
检查公开内容指纹、split 与校准人口交叉。新数据必须先转换成既有 PrefixRecord /
QueryRecord / FailureChainGold 格式并生成数据文件 manifest；这个入口不会帮你
制造真实轨迹或人工 gold。登记是否完整、语料是否真正独立仍需数据流程验证，
所以代码始终保留 `development_only=true`、`independent_validation=false`。

每个模型/预算单元有自己的中文报告和逐题失败表，包含首次/修复后合法率、硬检查、
语义裁判、证据、因果、安全、完整历史答对子集成绩及覆盖率。根报告列全部单元，
配对差异按前缀聚类 bootstrap（2000 次），不把同一前缀的三个问题当成独立样本。
这些区间用于探索，没有做多重比较修正。

成本分别列 construction / retrieval / answer / format_repair / reacquisition /
judge；同一个持久化 build job 只计一次。裁判不计入方法部署成本。另保存原档案
读出内容的 ID/token，包括读出但没有装进最终请求的记录。

```bash
uv run --extra server-eval python -m tracegraph.benchmark.server_eval score \
  --prepared runs/prepared --run runs/evaluation --output runs/rescored
```

旧 Flash pilot 的冻结目录不被改写。新增源码会改变实现指纹，因此以后运行旧
pilot 也必须重新 prepare 到新目录，不能把旧预检快照当成当前实现的证明。
