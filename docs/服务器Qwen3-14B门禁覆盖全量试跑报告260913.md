## 主轨结果：先不要读成记忆算法胜负

| 方法 | 主轨通过 | audit / hard pass rate | 平均证据 precision | 平均证据 recall | 部署 token |
|---|---:|---:|---:|---:|---:|
| Full history | 24/72 | 0.3333 | 0.9851 | 0.8889 | 241,950 |
| Recent masking | 24/72 | 0.3333 | 0.9557 | 0.8125 | 118,136 |
| Flat BM25 archive | 23/72 | 0.3194 | 0.9871 | 0.8958 | 92,953 |
| TraceGraph 0.4 | 24/72 | 0.3333 | 0.9940 | 0.8611 | 69,934 |

通过率的来源拆开后非常明确：

| query type | Full | Recent | BM25 | TraceGraph |
|---|---:|---:|---:|---:|
| `distractor_current` | 24/24 | 24/24 | 23/24 | 24/24 |
| `audit_chain` | 0/24 | 0/24 | 0/24 | 0/24 |
| `audit_failure_cause` | 0/24 | 0/24 | 0/24 | 0/24 |

因此，“TraceGraph 与 Full 同为 0.3333”不表示两者都解决了记忆问题；它们只是都答对了当前状态题，而历史追问全部失败。

部署 token 的口径是主问题 + 各方法一次共享构建，排除 calibration、diagnostic controls 和 judge。TraceGraph 使用 Full 的 28.9% token（少 71.1%）、Recent 的 59.2%（少 40.8%）、BM25 的 75.2%（少约 24.8%）。这是当前开发切片上的成本观察，不是质量等价条件下的正式效率结论。

## 诊断对照：有检索层信号，没有端到端成功

| 条件 | n | hard/audit pass | evidence precision | evidence recall | strict chain |
|---|---:|---:|---:|---:|---:|
| 删除失败链 | 8 | 0/8 | 0 | 0 | 0 |
| 等长无关内容 | 8 | 0/8 | 0 | 0 | 0 |
| Oracle | 8 | 0/8 | 1 | 1 | 1 |

在同一组 8 个诊断前缀的主轨 `audit_chain` 上，TraceGraph 的 evidence recall 和 strict chain 均为 8/8；Full 的 evidence recall 为 8/8，但 strict chain 只有 5/8（额外引用使严格链集合不再完全匹配）。

这组干预符合预期：移除必要内容会破坏证据恢复，恢复正确内容会恢复证据链，TraceGraph 的正式 policy 也能在这些前缀上选出链。但 Oracle、Full、TraceGraph 的端到端历史题仍全部失败，所以现阶段优先审核答案协议、严格值抽取、裁判判断和题目可执行性，而不是宣称图策略已被验证。

## TraceGraph 不是同名替身

开发 adapter 在 `src/tracegraph/benchmark/compression_audit/development_adapters.py` 第 13 行直接导入 `GraphConstrainedPolicy`，第 80 行实例化；`tracegraph_0_4` 在第 111–121 行调用正式 policy 的 `snapshot`，并在第 148–163 行调用 `materialize`。传给 policy 的只有公开问题文本，不含 track 或 required fields。

冻结 episode 的 artifact 同时记录：

- `implementation=tracegraph_0_4`
- `policy_class=tracegraph.context_engine.policy.GraphConstrainedPolicy`
- `policy_version=context_policy_v4`
- `future_query_observed=false`
- `hidden_gold_observed=false`
- snapshot hash、graph hash、policy plan、read/selected/retrieved span ID 和 token statistics

因此本轮的 TraceGraph 列确实来自正式 policy 路径，不是 recent truncation 或同名参考规则。

## 为真实运行修复的兼容性问题

本轮开始前后修复了三个会使试跑失真的兼容性问题，并补回归测试：

1. Transformers 5 的 `apply_chat_template` 可能默认返回字典，token 上界误数成字段数；现在显式 `return_dict=false`。
2. Qwen/vLLM 会在合法 JSON content 旁返回 `tool_calls: []`；parser 现在只把非空列表当作 tool-call transport，避免把全部答案误判为无效结构化输出。
3. 裁判提示澄清 `necessary_facts` 的 key、evidence ID 与 `claims_to_check` 的语义，并要求 contradiction 必须来自答案原文、严格抽取必须给出原文 quote 和 codepoint offset。

开发门禁覆盖也被实现为仅 live 模式可用的显式 CLI 开关 `--assume-gates-passed`，写入 run identity 和最终报告；离线模式不能使用，原始门禁结果不会被改写。

最终相关测试在本地为 99 passed；上传最终 bundle 后在服务器环境复核为 66 passed。
