# 外部基准主线决策与启动记录（2026-09-17）

## 1. 已冻结的研究决定

论文的核心外部评测改为以下三套 benchmark：

1. **AMA-Bench**：验证长轨迹记忆构建、检索和问答能力；
2. **tau3**：验证动态用户-工具-agent 交互中的端到端成功率、策略合规和 token 成本；
3. **AppWorld**：在 ACON 官方优先支持的长时程应用环境中比较任务成功率和上下文成本。

`compression_audit_v1` 继续承担受控机制验证，回答失败链、证据完整性和压缩率等问题，
但不作为唯一外部有效性证据。SWE/mini-SWE 不再阻塞主线，只保留为可选的模型能力探针或附录实验。

OfficeBench 暂不进入第一轮主矩阵。若三套主基准走通且资源允许，再将其作为第四套鲁棒性环境。

## 2. 各基准的不可替代角色

| 基准 | 主要研究问题 | 核心指标 |
|---|---|---|
| compression_audit_v1 | 方法是否保留失败链和回答所需证据 | 查询准确率、链完整率、压缩率 |
| AMA-Bench | 长轨迹压缩后能否正确检索并回答 | 回答分数、证据/检索分数、总 token |
| tau3 | 压缩是否影响在线多轮工具交互 | 任务成功率、策略合规、总 token、延迟 |
| AppWorld | TraceGraph 相比 ACON 是否有更好的成功率-成本权衡 | 状态评测通过率、总 token、延迟 |

tau3 的 retail/airline 等 domain 只是同一 benchmark 的不同域，不能在论文中当作多个独立 benchmark。

## 3. 正式比较方法

在接口允许且语义可比的条件下，固定比较：

- Full History；
- Recent Masking；
- BM25；
- Rolling Summary；
- official ACON；
- official AMA / AMA construction-retrieval adapter；
- TraceGraph。

若 AMA 的完整 agent 语义不能原样映射到 tau3 或 AppWorld，必须明确写成
`AMA construction/retrieval adapter`，不得声称完整复现 AMA-Agent。

所有方法使用相同基础模型、任务 ID、工具定义、agent 提示词、步数上限和随机种子。
成本必须包含记忆构建、压缩、检索和最终回答，不允许只报告最后一次模型调用。
运行时不得静默 fallback；失败和不兼容必须作为结果保留。

## 4. 数据污染与冻结规则

现有 `compression_audit_v1` 已使用 40 条 AMA-Bench 候选轨迹。所有已经查看、筛选、标注、
调试或用于开发的 AMA episode ID 都必须进入污染清单，不得放入正式确认性测试集。
正式 AMA-Bench 结果只能使用剩余未触碰 episode；已使用部分只能标记为 development 或 exploratory。

AppWorld 只允许在 train/dev 上调试方法与提示词。正式配置冻结后才可运行 `test_normal`；
`test_challenge` 留作最后的确认性评测。不得将测试集 ground truth 暴露给 agent。

tau3 官方任务用于外部有效性。若以后增加可控故障注入，必须单独标为项目 stress test，
不能称为官方 tau3 成绩。

## 5. 分阶段启动门禁

1. **环境 canary**：每个外部基准 3-5 题，验证数据、agent、评测器、usage 和断点恢复；
2. **可行性小样本**：每个基准约 20 题、单种子，检查信号、错误率和实际成本；
3. **配置冻结**：冻结方法版本、模型 endpoint、任务 ID、预算、种子和源码 commit；
4. **确认性实验**：扩大未污染样本，并只对关键随机条件补多种子；
5. **统计报告**：逐题配对差异、bootstrap 置信区间及成功率-token Pareto 前沿。

任何基准在 canary 中若出现 evaluator 无效、fallback、usage 缺失或数据泄漏，均不得进入下一阶段。

### 8.3 AMA-Bench 环境 canary

- Qwen thinking 在 AMA 的“长轨迹 + 12 个批量答案”提示上，于 temperature 0 和 1 均耗尽 8192 输出 token 且没有可见答案；两次运行记为配置门禁失败，不计入方法成绩。
- AMA 主比较因此在 benchmark 内冻结为 non-thinking direct-answer 解码；官方 LongContext 截断、问题、答案格式和数据均不改，且所有 AMA 方法必须使用同一解码配置。
- `full_history_qwen38_v3` 已完成 5/5 episode、60/60 问题、5 次 provider 调用、0 次重试；总用量为 prompt `181,918`、completion `8,090`、合计 `190,008` token。
- 使用 AMA-Hub 官方 LLM-as-judge 判分准则、以同一 Qwen3.8-27B 作为开发期裁判，得到 `31/60 = 51.7%`：spider2 `11/12`、swebench `1/12`、webarena `7/12`、alfworld `8/12`、gaia_level2 `4/12`。因此 AMA canary 不是全 0，但不同轨迹类型差异很大。
- swebench episode 的 12 个生成答案全部退化为占位文本 `Answer`，开发裁判仍误收其中 1 个，直接证明同模型裁判存在宽松偏差。60 个裁决中 10 个还需空响应协议修复（2 个 yes/no 后缀、4 个 binary non-thinking、4 个 binary thinking）；裁判调用及修复总用量为 prompt `90,461`、completion `14,424`、合计 `104,885` token。
- 所以 `51.7%` 只用于证明“存在非零信号”和定位失败类型，不得作为论文正式 AMA 成绩。进入约 20 条可行性实验前，必须固定一个独立强裁判，或至少对开发裁判结果做分层人工抽查；正式结果不能继续让答案模型自评。

### 8.5 Canary 门禁结论与下一步

- 三条外部基准都已出现非零信号：tau3 `4/5`、AMA 开发裁判 `31/60`、AppWorld 官方 evaluator `4/5`。这已经排除“新基准全部 0 分、无法区分题目与能力”的最坏情况，也说明没有必要回到 SWE-Bench 作为主线门禁。
